### 快手前端面试一面

1. **实现垂直水平居中的 5 种方案**
   - **flex 布局**：父元素设 `display: flex; justify-content: center; align-items: center;` 。
   - **grid 布局**：父元素 `display: grid; place-items: center;` 。
   - **绝对定位 + transform**：子元素 `position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%);` 。
   - **绝对定位 + margin: auto**：子元素 `position: absolute; top/bottom/left/right: 0; margin: auto;` ，需定宽高 。
   - **table 布局**：父元素 `display: table-cell; text-align: center; vertical-align: middle;` ，子元素 `display: inline-block;` 。
2. **事件循环机制：setTimeout、Promise、async/await 执行顺序**
   - 整体分**同步任务**（立即执行）、**微任务**（Promise.then 、async/await 中 await 后代码等，执行快于宏任务 ）、**宏任务**（setTimeout 、DOM 渲染等） 。
   - 执行流程：先完同步任务 → 清空微任务队列 → 取一个宏任务执行 → 再清空微任务队列，循环往复 。
   - 举例：`console.log(1); setTimeout(()=>{console.log(2)},0); Promise.resolve().then(()=>{console.log(3)}); async function fn(){ await Promise.resolve(); console.log(4)} fn();` ，执行顺序是 1 → 3 → 4 → 2 。
3. **React Hooks 的依赖数组作用原理**
   - 依赖数组是 `useEffect` 、`useCallback` 、`useMemo` 等 Hooks 的参数，用于确定 Hooks 何时重新执行 。
   - React 浅比较依赖数组前后值，若有变化，就会触发 Hooks 内逻辑重新运行；无变化则跳过，实现性能优化 。
4. **Vue 双向绑定原理及与 React 的差异**
   - **Vue 双向绑定**：基于 **Object.defineProperty** （Vue2 ）或 **Proxy** （Vue3 ）实现数据劫持，配合编译阶段对模板指令解析，数据变则视图更新，视图输入（如输入框）变则数据更新 。
   - **差异**：Vue 自动追踪依赖、双向绑定更直接；React 基于状态驱动，单向数据流，需手动触发更新（如 `setState` ），更强调数据流向可控性 。
5. **实现带缓存机制的斐波那契数列函数**
   - **思路**：用对象/Map 存已计算的斐波那契数，避免重复计算 。
   - **代码示例（JS）**：

```js
const fibCache = {};
function fib(n) {
  if (n <= 1) return n;
  if (fibCache[n]) return fibCache[n];
  fibCache[n] = fib(n - 1) + fib(n - 2);
  return fibCache[n];
}
```

1. **浏览器渲染原理与重绘回流优化**
   - **渲染原理**：解析 HTML 成 DOM 树、CSS 成 CSSOM 树 → 合并成渲染树 → 布局（计算元素位置大小，触发**回流** ）→ 绘制（像素渲染到屏幕，可能触发**重绘** ，如颜色变） 。
   - **优化**：减少回流（避免频繁改宽高、位置等，用 `class` 批量改样式；文档片段操作 DOM ）；减少重绘（避免不必要的样式变更，利用层合成） 。
2. **Webpack 的 Tree Shaking 实现原理**
   - 基于 ES6 模块静态结构（导入导出明确，编译时可分析），识别并删除未被使用的代码（“死代码” ） 。
   - 开启需：生产环境默认开启；`mode: 'production'` 、使用 ES6 模块语法、配置 `optimization.minimize` 等 。
3. **实现 Promise.all 的异常处理机制**
   - **逻辑**：所有 Promise 都 resolved ，返回结果数组；只要有一个 rejected ，立即返回该 rejection 。
   - **代码示例（JS）**：

```js
Promise.myAll = function (promises) {
  return new Promise((resolve, reject) => {
    const resArr = [];
    let count = 0;
    promises.forEach((p, idx) => {
      Promise.resolve(p)
        .then((res) => {
          resArr[idx] = res;
          count++;
          if (count === promises.length) resolve(resArr);
        })
        .catch(reject);
    });
  });
};
```

### 快手前端面试二面

1. **微前端架构落地方案及沙箱实现**
   - **落地方案**：基于路由（不同子应用对应不同路由，加载对应资源）、组合式（如 Web Components 封装子应用）等；常用框架如 Single-SPA 。
   - **沙箱实现**：隔离各子应用全局变量、样式等。**快照沙箱**（记录/恢复全局状态）、**代理沙箱**（用 Proxy 代理 window ，拦截读写，如 Vue3 微前端沙箱） 。
2. **如何实现前端路由？Hash 和 History 模式的区别**
   - **实现**：监听 URL 变化，匹配路由渲染对应组件。Hash 模式监听 `hashchange` 事件；History 模式用 `history.pushState` 、`replaceState` 配合 `popstate` 事件 。
   - **区别**：Hash 带 `#` ，不影响服务器路由；History 更美观，但需服务器配置（否则刷新 404 ，需重定向到入口页） 。
3. **解释浏览器渲染原理及关键渲染路径优化**
   - **渲染原理**：同一面试一第 6 题 。
   - **关键路径优化**：减少关键资源数量、降低关键资源大小、提前加载关键资源（如 `<link rel="preload">` ）；优化 CSS （避免阻塞渲染）、JS 执行（减少长任务） 。
4. **Webpack 构建优化有哪些具体措施？**
   - **优化速度**：多进程（`thread-loader` 、`happypack` ）、缓存（`cache-loader` 、`hard-source-webpack-plugin` ）、缩小打包范围（`exclude` 、`include` ） 。
   - **优化体积**：Tree Shaking 、代码压缩（`terser-webpack-plugin` ）、拆包（`splitChunks` ）、图片压缩（`image-webpack-loader` ） 。
5. **如何处理大文件分片上传？**
   - **流程**：前端用 `Blob.slice` 分片 → 逐个上传（带分片标识、总数等） → 后端接收拼接；可结合断点续传（记录已传分片，中断后继续传） 。
   - **关键**：分片算法、进度显示、错误重试、后端合并逻辑 。
6. **高并发场景下的前端性能优化策略**
   - **资源层面**：CDN 加速、按需加载（路由懒加载、组件动态导入）、缓存（HTTP 缓存、本地存储） 。
   - **渲染层面**：虚拟列表（如 `react-window` ）、节流防抖、避免频繁 DOM 操作；服务端渲染（SSR）/静态站点生成（SSG）减少首屏压力 。
7. **前端灰度发布实施方案**
   - **思路**：按规则（如用户 ID 、地域、比例）让部分用户访问新版本，其余用旧版。
   - **实现**：结合后端路由/网关控制；前端用特征标识（Cookie 、URL 参数）判断，加载对应资源；配合监控（错误、性能）收集反馈 。
8. **设计一个前端异常监控系统**
   - **捕获异常**：`try…catch` 、`window.onerror` （JS 错误）、`window.addEventListener('unhandledrejection')` （Promise 错误）、资源加载错误（`img.onerror` 等 ） 。
   - **上报数据**：错误信息（栈、消息）、用户行为（路由、操作）、设备信息（浏览器、系统）；通过 `fetch` 、`img` （简单）异步上报 。
   - **后台处理**：存储（数据库）、分析（聚合错误、统计趋势）、预警（邮件、IM 通知） 。
9. **大型 SPA 应用状态管理方案选型**
   - **Redux**：单向数据流、纯函数 reducer ，适合复杂交互、需严格状态追溯的场景；但样板代码多 。
   - **Mobx**：基于响应式，简洁灵活，自动追踪依赖，适合追求开发效率、中等复杂度应用 。
   - **Recoil（React 生态）**：React 官方思路，原子化状态管理，适合大型 React 应用拆分细粒度状态 。
   - **Pinia（Vue 生态）**：Vue 推荐，轻量、API 简洁，支持 Composition API ，替代 Vuex 。
10. **Serverless 在前端的应用场景**
    - **前端部署**：静态站点托管（如 Vercel ），自动部署、CDN 加速 。
    - **后端逻辑**：用云函数（如 AWS Lambda 、腾讯云函数 ）处理接口、数据校验、文件处理等，前端直连云函数，无需自建服务器 。
    - **边缘计算**：靠近用户节点运行函数，降低延迟，如边缘渲染、实时数据处理 。
