## 一、代码题

### 找出数组中字符串的最长公共前缀

**题目描述**：编写一个函数来查找字符串数组中的最长公共前缀。如果不存在公共前缀，返回空字符串 `""` 。
**示例**：
输入：`["flower","flow","flight"]`
输出：`"fl"`
**解题思路**：

1. 若数组为空，直接返回空字符串。
2. 取第一个字符串作为初始前缀，依次与后续字符串对比，不断缩短前缀，直到找到所有字符串都包含的公共前缀。
   **代码实现（JavaScript）**：

```javascript
function longestCommonPrefix(strs) {
  if (strs.length === 0) return "";
  let prefix = strs[0];
  for (let i = 1; i < strs.length; i++) {
    while (strs[i].indexOf(prefix) !== 0) {
      prefix = prefix.slice(0, prefix.length - 1);
      if (prefix === "") return "";
    }
  }
  return prefix;
}
```

## 三、技术对比与框架相关

### 有没有对比其他除了 formily 库

在表单解决方案选型中，对比过以下库：

- **Ant Design Form（React 生态）**：
  - **优势**：与 AntD 组件库深度集成，生态完善，文档示例丰富，上手成本低，适合中后台简单到中等复杂度表单。
  - **不足**：复杂表单逻辑（如动态表单、跨字段联动校验）需大量自定义代码，表单状态管理相对基础，缺乏可视化配置、复杂布局编排能力。
- **Vue Formulate（Vue 生态）**：
  - **优势**：提供简洁 API，支持表单验证、动态字段、自定义渲染器，对 Vue 生态友好，内置多种常用验证规则，可扩展插件丰富。
  - **不足**：社区生态相对 Formily、AntD Form 较小，在复杂企业级表单场景（如多步骤表单、大规模表单校验）的成熟方案案例少。
- **Final Form**：
  - **优势**：轻量级、高性能，专注表单状态管理，可与任意 UI 库集成，支持订阅式状态更新，适合对表单性能要求高、需深度定制 UI 的场景。
  - **不足**：需手动搭建表单渲染逻辑，没有开箱即用的组件，开发成本高于 Formily 等一站式方案。

对比后，Formily 在复杂表单场景（动态表单、可视化配置、跨端适配）的优势明显，其响应式设计、丰富的扩展插件（如表单设计器、适配器），能更好支撑美团业务中台多场景表单需求，但其他库在特定简单场景也有各自适用价值。

### 移动端的 formily 有没有性能问题

在美团移动端（如美团 App 内嵌 H5、美团小程序）使用 Formily 时，需关注以下性能点，合理优化可避免明显性能问题：

- **渲染性能**：
  - 若表单字段极多（如超过 50 个动态联动字段 ），Formily 的响应式更新可能触发较多重渲染。可通过 `useMemo`、`useCallback` 缓存组件与回调，减少不必要渲染；或拆分表单为多个子表单，按需加载与渲染。
  - 移动端设备性能差异大（如低端安卓机 ），复杂表单的初始化渲染可能卡顿，可结合动态导入（`dynamic import` ）、骨架屏占位，优化首屏加载体验。
- **内存占用**：
  - Formily 会维护表单状态树，复杂表单的状态对象可能较大。需注意及时销毁无用表单实例（如页面卸载时清理表单订阅），避免内存泄漏；合理使用 `resetFields` 等方法重置表单状态，释放内存。
- **网络交互**：
  - 若表单联动依赖频繁接口请求，需做好请求节流、防抖，避免因网络延迟或请求堆积导致表单响应缓慢。可结合本地缓存、预加载策略，优化数据交互流程。

总体而言，Formily 本身做了性能优化（如响应式更新的依赖收集优化 ），但在移动端复杂场景下，需结合业务做针对性优化，实际项目中通过合理编码与监控，可保障性能满足业务需求。

## 四、技术原理与实现

### 1. 如果转 react native 需要具备什么

若从 Web 前端（如 React 技术栈）转 React Native 开发，需补充以下知识与技能：

- **React Native 基础**：
  - 掌握 RN 组件（如 `View`、`Text`、`TouchableOpacity` ）与 Web 组件差异，熟悉 RN 样式写法（类似 CSS 但有适配，如 `StyleSheet.create` 、布局用 `Flexbox` ）。
  - 理解 RN 桥接原理（JavaScript 与原生 iOS/Android 通信机制 ），知道如何调用原生模块（如相机、定位 ），处理平台特定功能。
- **跨端适配能力**：
  - 处理 iOS、Android 两端差异，如字体、手势、系统级交互（安卓返回键、iOS 导航栏 ），学会用 `Platform` API 做条件渲染。
  - 适配不同设备屏幕、分辨率，利用 `Dimensions`、响应式布局方案（如 `react-native-responsive-screen` ）保障 UI 一致性。
- **性能优化经验**：
  - 了解 RN 性能瓶颈点（如列表渲染、大图加载 ），掌握 `FlatList` 等高性能组件使用，学会内存管理、避免不必要的重渲染（如 `useMemo`、`PureComponent` ）。
- **工具与生态**：
  - 熟悉 RN 开发工具链（如 `Expo` 、`react-native-cli` ），掌握调试方法（如 Flipper 调试工具 ），了解常用第三方库（如导航库 `react-navigation` 、状态管理 `redux`/`mobx` 适配 RN ）。

### 2. react hooks 为什么不能用在循环里

**原理**：React Hooks 依赖 **“调用顺序一致性”** 工作。

- React 内部用**链表**维护组件 Hooks 状态，组件每次渲染，Hooks 调用顺序必须与初始渲染完全一致，才能正确关联状态（如 `useState` 的状态值、`useEffect` 的依赖监听 ）。
- 若在循环（`for`、`while` ）里调用 Hooks，循环次数变化会破坏调用顺序，导致 Hooks 链表错位，React 无法正确识别每个 Hook 对应的状态，引发状态混乱、报错（如 `Rendered more hooks than during the previous render` ）。

**示例**：

```javascript
// 错误写法：Hooks 在循环中，顺序不稳定
function MyComponent() {
  const [count, setCount] = useState(0);
  for (let i = 0; i < count; i++) {
    // 每次 count 变化，useEffect 调用次数改变，破坏顺序
    useEffect(() => {
      /* ... */
    }, [i]);
  }
  return <div>{count}</div>;
}
```

### 3. react fiber 怎么实现的

React Fiber 是 React 16+ 重构的**异步可中断渲染架构**，核心实现逻辑：

- **工作单元拆分**：
  将虚拟 DOM 渲染任务拆分为**小 Fiber 节点（工作单元）**，每个 Fiber 记录组件更新优先级、状态、依赖等信息，让渲染过程可被中断、恢复。
- **调度机制**：
  引入**调度器（Scheduler）**，基于浏览器 `requestIdleCallback`（或 polyfill ），在浏览器空闲时间（如帧间隙）执行高优先级 Fiber 任务（如用户交互触发的更新 ），低优先级任务（如大列表渲染 ）暂停等待，避免阻塞主线程，保障页面响应。
- **双缓存与渲染流程**：
  维护**两个 Fiber 树（current 树、workInProgress 树 ）**，current 树对应当前渲染的 DOM，workInProgress 树记录更新中的 Fiber 状态。更新时在 workInProgress 树异步构建新结构，完成后与 current 树替换，实现快速更新，同时支持回退（若任务被中断，保留当前进度 ）。

简单说，Fiber 通过拆分任务、优先级调度、双缓存树，让 React 渲染更灵活高效，避免卡顿，适配复杂大型应用场景。

### 4. 有没有实现过 webpack 的 plugin，原理是什么

**实现过的场景**：开发美团业务组件库时，需自动给构建后的组件代码注入版权声明、版本信息，实现过简易 Webpack Plugin。
**Plugin 代码示例（简化版）**：

```javascript
class AddCopyrightPlugin {
  apply(compiler) {
    // 注册 compilation 钩子，编译阶段执行
    compiler.hooks.compilation.tap("AddCopyrightPlugin", (compilation) => {
      // 注册优化阶段钩子，处理 chunk
      compilation.hooks.optimizeChunkAssets.tapAsync("AddCopyrightPlugin", (chunks, callback) => {
        chunks.forEach((chunk) => {
          chunk.files.forEach((file) => {
            // 给每个输出文件头部添加版权信息
            const copyright = `/** © 2024 美团公共技术团队 */\n`;
            const originalCode = compilation.assets[file].source();
            compilation.assets[file] = {
              source: () => copyright + originalCode,
              size: () => (copyright + originalCode).length,
            };
          });
        });
        callback();
      });
    });
  }
}

module.exports = AddCopyrightPlugin;
```

**原理**：
Webpack 基于**插件化架构（Tapable 库）**，Plugin 通过**钩子（Hook）** 介入编译流程。

- **Tapable 机制**：Webpack 核心对象（`compiler`、`compilation` ）暴露大量钩子（如 `compilation`、`optimizeChunkAssets` ），Plugin 通过 `tap`/`tapAsync` 注册钩子回调，在特定编译阶段执行逻辑。
- **编译流程干预**：Plugin 可读取、修改 Webpack 编译过程中的资源（如代码块 `chunk`、输出文件 `assets` ），实现自定义功能（如注入内容、优化资源、替换代码 ）。

简单说，Webpack Plugin 是通过监听、干预编译钩子，实现对构建流程的扩展，满足个性化需求（如代码注入、资源优化、自定义打包逻辑 ）。

### 5. 实现两个栈实现队列

**需求**：用两个栈（`stackIn`、`stackOut` ）模拟队列的**先进先出（FIFO）** 特性，支持 `enqueue`（入队 ）、`dequeue`（出队 ）操作。
**思路**：

- `stackIn` 负责**入队**：新元素 push 到 `stackIn` 。
- `stackOut` 负责**出队**：若 `stackOut` 为空，将 `stackIn` 元素全部 pop 并 push 到 `stackOut`（实现顺序反转，模拟队列顺序 ）；若 `stackOut` 非空，直接 pop 栈顶元素（队列首元素 ）。

**代码实现（JavaScript）**：

```javascript
class QueueWithTwoStacks {
  constructor() {
    this.stackIn = []; // 入队栈
    this.stackOut = []; // 出队栈
  }

  // 入队
  enqueue(value) {
    this.stackIn.push(value);
  }

  // 出队
  dequeue() {
    if (this.stackOut.length === 0) {
      // stackOut 为空，将 stackIn 元素转移过来
      while (this.stackIn.length > 0) {
        this.stackOut.push(this.stackIn.pop());
      }
    }
    // stackOut 非空，弹出栈顶（队列首元素）
    return this.stackOut.pop();
  }
}

// 测试
const queue = new QueueWithTwoStacks();
queue.enqueue(1);
queue.enqueue(2);
console.log(queue.dequeue()); // 输出 1（队列先进先出）
queue.enqueue(3);
console.log(queue.dequeue()); // 输出 2
```
