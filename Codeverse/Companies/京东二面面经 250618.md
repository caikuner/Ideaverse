## 1. 描述最近使用的前端框架及选择原因

我最近主要使用 React 和 Vue 3。选择 React 是因为其庞大的生态系统、组件化开发模式和虚拟 DOM 的高效渲染，特别适合大型复杂应用。选择 Vue 3 是因为其简洁的 API 设计、优秀的性能提升（如 Composition API）和渐进式框架特性，适合快速开发中小型项目。

## 2. React 中大列表渲染性能优化

- **虚拟列表技术**：只渲染可视区域内的元素（react-window, react-virtualized）
- **分页/懒加载**：分批加载数据
- **shouldComponentUpdate/PureComponent/React.memo**：避免不必要的重新渲染
- **key 属性优化**：使用稳定唯一标识而非数组索引
- **避免内联函数和对象**：减少不必要的重新渲染

## 3. Vue 3 相比 Vue 2 的重要改进

- **Composition API**：更好的逻辑复用和代码组织
- **性能提升**：基于 Proxy 的响应式系统，更快的渲染和更小的包体积
- **更好的 TypeScript 支持**
- **多根节点组件**（Fragment）
- **Teleport 组件**：将子节点渲染到 DOM 其他位置
- **Suspense 组件**：更好的异步组件处理
- **自定义渲染器 API**

## 4. Web Workers 提高页面性能

Web Workers 允许在后台线程运行 JavaScript，不阻塞主线程：
- **计算密集型任务**：如图像处理、大数据计算
- **长时间运行脚本**：避免 UI 冻结
- **轮询和后台同步**：不影响用户体验
- 使用方式：`new Worker('worker.js')`，通过 `postMessage` 通信

## 5. CSS Grid 与 Flexbox 适用场景

**Flexbox**：
- 一维布局（行或列）
- 内容驱动的布局（项目大小由内容决定）
- 对齐和分布空间
- 导航栏、卡片布局等

**CSS Grid**：
- 二维布局（行和列）
- 精确控制布局结构
- 复杂的页面布局
- 杂志式布局、仪表盘等

## 6. JavaScript Event Loop 及宏任务/微任务

Event Loop 是 JavaScript 处理异步代码的机制，包含：
- **调用栈**：执行同步代码
- **任务队列**：宏任务（setTimeout, setInterval, I/O）
- **微任务队列**：微任务（Promise.then, MutationObserver）

执行顺序：同步代码 → 微任务 → 渲染 → 宏任务

## 7. 模块加载器基本原理

实现一个模块加载器需要：
1. 模块定义：每个文件是一个模块，有独立作用域
2. 依赖分析：解析模块依赖关系（如 AST 分析）
3. 加载机制：动态创建 script 标签或 XHR 加载
4. 缓存机制：避免重复加载
5. 执行顺序：保证依赖顺序正确

## 8. 静态站点生成器工作原理及选择

**工作原理**：
- 构建时预渲染所有页面为静态 HTML
- 可能使用模板和数据源生成页面
- 部署到 CDN 实现快速加载

**选择考虑**：
- 项目规模：Next.js/Gatsby（大型），Hugo（小型）
- 技术栈：React（Next.js），Vue（Nuxt.js）
- 功能需求：是否需要 SSR/ISR
- 构建速度：Hugo 极快，Gatsby 较慢

## 9. 前端依赖管理和优化

- **锁定版本**：使用 package-lock.json/yarn.lock
- **定期更新**：`npm outdated` + `npm update` => taze
- **依赖分析**：`npm ls` 或 webpack-bundle-analyzer
- **按需加载**：只引入需要的库部分
- **删除无用依赖**：`depcheck`
- **代码分割**：动态 import()
- **CDN 加载**：常用库如 React, Vue

## 10. SSR 与 CSR 差异及优势

**SSR (Server-Side Rendering)**：
- 优势：更好的 SEO，更快的首屏加载，对低端设备友好
- 劣势：服务器压力大，开发复杂度高，TTI 可能较慢

**CSR (Client-Side Rendering)**：
- 优势：丰富的交互，前后端分离，减轻服务器压力
- 劣势：SEO 困难，首屏加载慢，对 JavaScript 依赖强

## 11. 防止 XSS 和 CSRF 攻击

**XSS 防护**：
- 输入输出转义（如 DOMPurify）
- 使用 Content Security Policy (CSP)
- 避免 innerHTML，使用 textContent
- HttpOnly cookie

**CSRF 防护**：
- 使用 CSRF token
- SameSite cookie 属性
- 检查 Referer 头部
- 关键操作二次验证

## 12. WebSockets 实现实时通信

```javascript
const socket = new WebSocket('wss://example.com');

socket.onopen = () => {
  socket.send('Hello Server!');
};

socket.onmessage = (event) => {
  console.log('Message from server:', event.data);
};

socket.onclose = () => {
  console.log('Connection closed');
};
```

优势：全双工通信，低延迟，适合聊天、实时游戏、股票行情等场景。

## 18. 树摇（Tree Shaking）原理

Tree Shaking 是通过静态分析移除 JavaScript 中未使用的代码。工作方式：
1. ES6 模块系统（import/export）是静态的
2. 打包工具（如 Webpack）分析依赖关系
3. 确定哪些导出未被使用
4. 在最终包中排除这些代码

需要配合压缩工具（如 Terser）实现最佳效果。
