## 浏览器从输入 url 到显示网页的全过程

[[浏览器：从输入 url 到页面展示的全过程 ⭐️]]

这个问题的答案内容比较多，回答的时候不一定要答的多细致，但一定不要错过关键步骤。

- DNS 解析出 IP 地址
- 建立 TCP 连接
- 客户端发出 HTTP 请求
- 服务端响应 HTTP 请求
- 浏览器解析 HTML CSS
- 渲染 DOM
- 执行 JS 代码，可能会 ajax 加载内容，再次渲染 DOM
- 加载媒体资源
- 浏览器缓存机制

## React 和 Vue 有什么区别？更擅长哪一个？

最近两年主要使用的技术栈是 React 相关的，不过我在导师公司实习也使用了 Vue2 技术栈一年，也相对熟悉一些。

[[React 与 Vue 的主要异同对比]]

主要的区别

- 设计哲学：Vue 渐进式、语法糖便于使用；React 函数式编程，API 简洁，更符合 JS 原生编程习惯
- 语法：Vue 默认使用 Vue template 模板语法（也支持 JSX）；React 默认使用 JSX 语法
- 数据绑定：Vue 通过依赖收集和触发实现自动响应；React 手动 setState
- 状态管理：Vue 可变数据；React 推荐不可变数据；
- 组件化：React 使用 Hooks ，有调用顺序、闭包陷阱等心智负担；Vue3 使用 composables 组合式 API ，心智负担少
- 性能优化：Vue 依赖精确，自定处理性能问题；React 手动处理 usememo/usecallback

## 如何做好技术选型？

当在工作中选择一个 语言/框架/工具 时，需要考虑什么？

- 活跃程度：
  - 社区热门程度，搜索引擎和 StackOverflow 上能搜出多少相关资料？
  - 参考 GitHub star 数量和 npm 下载量
- 稳定性：
  - 创办时间和发展时间，不要用太新的技术，首先要求稳
- 生态完善：
  - 看社区生态的完善程度，第三方的 UI 、组件、插件等，都是否完善
- 团队成本：
  - 团队成员的学习成本、熟悉程度
- 开发效率

举个例子：

- 选择 React，就是因为它生态最好、而且团队内最熟悉
- 选择 Vite，生态比较完善、比较热门 多数技术栈的默认推荐、开发效率
- 选择 Vitest，是因为和 Vite 集成、热门、API 友好且兼容 Jest

## 如何理解技术方案设计？是否做过技术方案设计？

技术方案设计，就是根据业务需求分析，把要开发的内容，落成详细设计文档，说明一下自己要怎么开发，并经团队成员评审。**这有利于**：

- 落实业务真正需求，避免无效设计、过度设计
- 发现在落地时可能遇到的棘手问题，同步各方做好风险预期
- 多人视角发现设计方案的不足，比如：更好的实现、功能重复、性能瓶颈、安全隐患等
- 评估人力
- 沉淀项目文档，便于后续项目维护

当然一些简单的需求就不太需要文档了。

技术方案设计一般包含如下部分：

- 主要需求分析
- 方案设计：总体设计，各模块详设
  - 总体流程
  - 详细说明各路由和模块详设
  - 权限
  - 组件 UI 结构，嵌套关系，属性如何传递
  - state 数据结构，如会存储在 vuex 或 redux 中
  - 会用到哪些服务端的 API ，哪些是现有的，哪些需要新开发
  - 如有复杂逻辑，详细说明流程
- 测试、上线方案
- 是否有性能隐患？
- 是否有安全隐患？

## 线上出了严重 bug 你该如何解决？

- **回滚**，及时止损 —— 这一步最重要，先止损，再溯源
- 定位有问题的上线
  - 通知项目组成员，看谁最近有过上线？—— 线上 bug 一般是最近一次上线导致的
- 在本地或测试环境复现 bug，查找原因
- 修复，测试，重新上线
  - 这里可以积累一些快速修复的经验，比如配置化、热更新等
- **复盘**会议，以后如何规避此类问题
- 另外，项目有必要增加监控报警，这样线上有 bug 会及时抛出。

## 参与的项目，研发流程是怎样的？

如果是新项目研发，会采用传统的瀑布流形式：

- 项目立项
- 确认需求，编写需求文档，UI 设计图，评审 （MRD，PRD，设计图）
- 制定技术方案，评审
- 制定研发计划、排期
- 开发，至少每周有一次进度对齐，排查延期风险，保证风险可控
- 多端联调
- 测试，修复 bug
- 上线
- 线上回归，总结

![[前端 Leader 面试  前端面试派-UjzAnAxRoL.jpeg]]

如果是已有项目的维护和升级，一般采用敏捷开发方式：

- 每个项目有一个统一的任务列表，分优先级排列
- 开发人员按照优先级领取一个任务，负责设计、开发、提测等流程，每一步都会在任务看板中显示步骤和进展
- 待这个任务上线以后，再领取下一个任务

## 如何保障代码质量？

代码质量和系统稳定性有直接关系，保障代码质量也是高级程序员的必备技能。

- 配置统一的 eslint 和 prettier 规则，规范代码格式。包括 precommit、lint-stage 等
- 每次代码合并，都进行 code review ，外加每周一次团队 code review
- 编写单元测试，提交 commit 时自动触发单元测试
- 使用 Sentry 等平台进行线上错误报警，并及时修复问题

## 是否写过单元测试和 e2e 测试？

单元测试，是针对某个小型单元（组件，函数），常见的工具 Jest Vitest

## 如何实现 ajax 并发请求控制？ [[https://www.mianshipai.com/docs/third-exam/leader-test.html#如何实现-ajax-并发请求控制]]

[[TaskScheduler.js]]

解题思路

- Promise.all 是需要固定数量的，并不适用这个题目的场景

## 最近在看什么书？或者学什么新技术吗？

如果你的简历写了自我评价，且在自我评价中写了“热爱技术” “持续学习”等描述，很可能会被问到这个问题。当然，你不写也不一定就不会被问到，还是提前准备好吧。

### **1. 最近阅读的书籍**

- 《Vue3 设计与实现》：学习 Vue3，之前熟悉 Vue2，补全技术栈。
- **《TypeScript 从入门到进阶》**：之前业务使用的少。学习 TS 类型系统、泛型、装饰器等，适应 Vue 3 和 React 18 的 TS 趋势。
- **《JavaScript 权威指南（第 7 版）》**（犀牛书）：复习。 深入理解 JavaScript 核心概念，包括 ES2020+ 新特性、异步编程、模块化等，适合夯实基础。
- **《Webpack 实战：入门、进阶与调优》**：掌握现代前端构建工具，优化打包性能，适应大厂工程化需求。

（如果时间允许，可补充《CSS 揭秘》《数据结构与算法 JavaScript 描述》等，体现全面性）

---

### **2. 关注的新技术与行业进展**

#### **（1）AI 驱动的前端开发**

- **AI 全流程辅助**：如 Claude Code 自动生成 UI 代码、修复 Bug，减少手动编码量，提升开发效率。
- **自然语言编程**：Vercel 的 `v0` 工具可通过描述生成 React/Tailwind 代码，未来可能支持 Nuxt.js（Vue 生态）。
- **AI 测试与优化**：AI 自动生成测试用例、分析 Lighthouse 报告并优化性能。

#### **（2）边缘计算与前端性能**

- **本地化数据处理**：边缘节点（如 WebAssembly）减少云端依赖，提升实时交互体验（如在线协作工具的延迟降低 70%）。
- **离线能力增强**：Service Worker + 边缘存储，使 Web 应用在弱网环境下仍可用。

#### **（3）框架与工具演进**

- Vue 发布 ValorMode，去除 DOM
- Node 全栈，服务端渲染
  - 如 Next.js 框架，这两年发展很迅速
  - **Vercel 收购 Nuxt.js**：React（Next.js）和 Vue（Nuxt.js）的 SSR 方案统一，部署体验优化。
- Vite/Rolldown/Turbopack/rspack 替代 Webpack
  - 基于 Rust 的极速构建工具，编译速度提升 10 倍。
- **微前端架构成熟**
  - 大型应用拆分为独立模块，支持多技术栈共存（如 qiankun、Module Federation）。
- Nginx 支持 JS 语法（quickjs，es2023）

#### **（4）WebAssembly（Wasm）突破**

- **高性能计算**：C++/Rust 代码在浏览器运行，适用于 3D 渲染、音视频处理等场景。
- **跨语言开发**：前端可集成 Rust 模块，提升性能敏感任务的效率。

### **3. 结合个人实践的总结**

- **学习路径**：从经典书籍打基础，再跟进 AI、边缘计算等前沿技术。
- **技术选型**：根据项目需求选择趋势技术（如 AI 生成 UI 用于快速原型，Wasm 用于高性能计算）。
- **社区动态**：关注 Vercel、Nuxt.js 等生态变化，参与开源讨论或实验性项目。

## 你的优缺点是什么？

注意，这是个坑！不要傻乎乎的真把自己的缺点说出来，暴露给别人看。

正确的方式是：

- 说优点，也和工作相关，不要太大，具体一些
- 说缺点，也要说自己的补救措施，最终体现自己是一个爱学习、要求进步的人。

推荐的表达方式

- 我觉得自己的知识目前在 AI 方面还有所欠缺
- 但我已经列了计划开始学习这方面的知识了，像 AI-for-Beginer、AI roadmap，面试差不多有结果以后我就开始钻研一下，计划 xxx 天以后即可完成
- 你的优点缺点是什么
  - 优点：做事仔细认真，能专注做一件事
  - 缺点：常常只能同时做一件重要的事，比如之前同时负责好几个项目
    - 改进：
      - 借助一些效率工具，如待办、看板、linear，来帮助自己合理安排
      - 规定时间处理杂事
  - 优点：乐于接受探索新技术
  - 缺点：之前因为我们部门的业务模式是工程和策略完全分开，可能对末端的业务收益这块把控不够，后续会加强
