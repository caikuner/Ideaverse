### 进程与线程

在讲浏览器架构之前，先理解两个概念，`进程` 和 `线程`。

进程（process）是程序的一次执行过程，是一个动态概念，是程序在执行过程中分配和管理资源的基本单位。
线程（thread）是 CPU 调度和分派的基本单位，它可与同属一个进程的其他的线程共享进程所拥有的全部资源。

简单说，进程可以理解成正在执行的应用程序；线程，可以理解成应用程序中的代码的执行器。而他们的关系可想而知，**线程是跑在进程里面的**，一个进程里面可能有一个或者多个线程，而一个线程，只能隶属于一个进程。

- 进程启动后可以以多线程的方式调度计算机资源
  **浏览器是一个应用，应用程序的一次执行，可以理解为计算机启动了一个 `进程`。**
  **进程启动后，CPU 会给该进程分配相应的内存空间，当进程得到了内存之后，就可以使用 `线程` 进行资源调度，进而完成我们应用程序的功能。**

- 一个应用程序可以启动多个进程，达到任务隔离的目的
  而在应用程序中，为了满足功能需要，启动的进程可能会创建另外的新的进程来处理其他任务，这些创建出来的新的进程拥有全新的独立内存空间，不与原来的进程共享内存。如果这些进程之间需要通信，可以通过 IPC 机制（Inter Process Communication）来进行，比如消息传递、共享内存等方式。

很多应用程序都会采取这种多进程的方式来工作，因为进程和进程之间是互相独立，它们 `互不影响`，当其中一个进程挂掉了之后，不会影响到其他进程的执行，只需要重启挂掉的进程就可以恢复运行。

### 浏览器的多进程架构

浏览器的多进程架构通常包括以下核心进程：

1. **浏览器主进程（Browser Process）**：管理界面（地址栏、书签等）、网络请求、文件访问等。
2. **渲染进程（Renderer Process）**：每个标签页独立进程，负责 HTML/CSS/JS 解析、渲染（Blink/V8 引擎运行在此，**JS 单线程执行**）。
3. **GPU 进程（GPU Process）**：加速页面渲染、3D 图形处理。
4. **插件进程（Plugin Process）**：每个插件（如 Flash）独立运行，已逐步淘汰。
5. **网络进程（Network Process）**：Chrome 新架构中独立处理网络请求（如 HTTP 缓存、DNS）。
6. **工具进程（Utility Processes）**：运行扩展程序、Service Workers 等。

**特点**：

- 进程隔离（崩溃不影响整体），安全性高，但内存占用较大
- 进程间通信：如 Chrome 使用 Mojo 框架统一 IPC，支持高效跨进程调用（类似 RPC）。

进程间协作：

比如，当要浏览一个网页，在浏览器的地址栏里输入 URL

> 详细版参见 [[浏览器：从输入 url 到页面展示的全过程 ⭐️]]

- Network Process 尝试去命中网页缓存，如果没有命中，就去解析 DNS(先尝试命中 DNS 缓存)
- Browser Process 向这个 URL 发送请求，获取这个 URL 的 HTML 内容
- 将 HTML 交给 Renderer Process，Renderer Process 解析 HTML 内容，构建 DOM 等，最终生成图像帧
- 解析完成后，Renderer Process 计算得到图像帧，并将这些图像帧交给 GPU Process，GPU Process 将其转化为图像显示屏幕。

在这之中，渲染进程的操作是开发者最需要关注的。

### 渲染进程

#### 进程模式

Renderer Process 的作用是负责一个 Tab 内的显示相关的工作，这就意味着，一个 Tab，就会有一个 Renderer Process，这些进程之间的内存无法进行共享。

为了节省内存，Chrome 提供了四种进程模式（Process Models），不同的进程模式会对 tab 进程做不同的处理。

- Process-per-site-instance (**default**) - 同一个 site-instance 使用一个进程
- Process-per-site - 同一个 site 使用一个进程
- Process-per-tab - 每个 tab 使用一个进程
- Single process - 所有 tab 共用一个进程

其中，site 和 site-instance 的定义

- site：相同的 registered domain name (如：google.com ，bbc.co.uk) 和 scheme (如：https://)。
  - 子域名也可以，比如 a.baidu.com 和 b.baidu.com 就可以理解为同一个 site
  - 不同端口也可以
  - 注意：这里要和 Same-origin policy 区分开来，同源策略会限制子域名和端口
- site-instance 指的是一组 connected pages from the same site
  - 这里 connected 的定义是 can obtain references to each other in script code
  - 满足下面两中情况并且打开的新页面和旧页面属于上面定义的同一个 site，就属于同一个 site-instance
    - JS 代码打开的新页面（比如 window.open)
    - 用户通过 `<a target="_blank">` 这种方式点击打开的新页面

默认模式选择：Process-per-site-instance，既可以少开进程，也可以很好隔离同域名下的无关 tab。

#### 多线程调度

Chrome 渲染进程（Renderer Process）是多进程架构的核心部分，负责处理标签页内的所有内容（HTML、CSS、JavaScript、布局、绘制等）。它内部运行着多个**常驻线程**，协同工作以高效地渲染网页内容。

1. **主线程（Main Thread / Renderer Main）**：
   - **核心线程**，负责绝大多数关键任务。
   - **职责**：
     - **解析 HTML**：构建 DOM 树。
     - **解析 CSS**：构建 CSSOM 树。
     - **JavaScript 执行**：执行页面中的 JavaScript 代码（事件处理、DOM 操作、API 调用等）。
     - **样式计算（Style Calculation / Recalc Style）**：将 CSS 规则应用到 DOM 节点上，计算每个节点的最终样式。
     - **布局（Layout / Reflow）**：计算每个 DOM 节点在视口中的确切几何位置（位置、大小）。构建布局树（Layout Tree）或渲染树（Render Tree）。
     - **图层更新（Update Layer Tree）**：确定哪些元素需要独立的图层（如 `transform`, `will-change` 等属性）。
     - **绘制记录生成（Paint Recording / Generate Display List）**：将布局树分解为绘制操作列表（类似于绘图命令），但不执行实际绘制。生成绘制列表（Paint Records）。
     - **事件处理**：处理用户输入事件（点击、滚动、键盘输入等）。
     - **网络请求（部分）**：发起子资源请求（如图片、脚本）。
     - **垃圾回收（GC）**：V8 引擎的垃圾回收主要在主线程上执行（Stop-The-World 暂停）。
   - **关键点**：这是最繁忙、最容易成为性能瓶颈的线程。长时间的 JavaScript 执行、复杂的布局或样式计算都会阻塞主线程，导致页面卡顿或无响应。

2. **合成线程（Compositor Thread）**：
   - **职责**：
     - **接收图层信息**：从主线程接收图层树（Layer Tree）和绘制记录（Paint Records）。
     - **分块（Tiling）**：将图层分割成更小的图块（Tiles）。
     - **调度光栅化**：将图块发送给光栅线程池进行光栅化。
     - **合成帧（Compositing Frame）**：收集光栅化完成的图块，结合滚动、缩放、动画（特别是 CSS `transform`/`opacity` 动画）等信息，计算出一个完整的“帧”（Frame）。
     - **提交帧给 GPU 进程**：将计算好的帧（包含绘制图块的指令和纹理）提交给 GPU 进程（Browser Process）进行最终的屏幕绘制。
     - **处理输入事件（初步）**：接收来自浏览器进程的输入事件（如滚动）。如果是非阻塞的滚动（比如页面没有监听 `scroll` 事件），合成线程可以**直接**处理滚动，更新图层位置并合成新帧（**快速滚动路径**），无需唤醒主线程，实现极其流畅的滚动体验。如果事件需要主线程处理（如 `click` 事件或页面监听了 `scroll`），则会将事件信息转发给主线程。
   - **关键点**：该线程独立于主线程运行，使得滚动和某些动画（尤其是利用 `transform` 和 `opacity` 的）可以非常高效，即使主线程繁忙也能保持流畅。

3. **光栅线程池（Raster Worker Thread Pool）**：
   - **数量**：通常由多个工作线程组成（数量取决于 CPU 核心数）。
   - **职责**：
     - **光栅化（Rasterization）**：将合成线程传递过来的图块（Tiles）和绘制记录（Paint Records）**转换成位图（Bitmap）**。本质上就是将绘制命令（矢量指令）转换成屏幕上的实际像素点。
     - 这个过程通常使用 GPU 进行加速（称为 **GPU Rasterization**），如果 GPU 不可用或资源不足，则回退到 **Software Rasterization**（由 CPU 执行）。
   - **关键点**：将计算密集型的像素生成工作并行化到多个线程，显著提高了渲染效率。

4. **JavaScript 引擎线程（V8 相关线程）**：
   - 虽然 JavaScript *执行*发生在主线程上，但 V8 引擎内部会利用额外的线程来优化性能：
     - **编译线程（Compiler Threads）**：在后台将 JavaScript 代码编译（或优化编译）成机器码，不阻塞主线程执行。
     - **Profiler 线程**：收集运行时性能分析数据，用于指导优化编译。
     - **垃圾回收辅助线程（Concurrent/Parallel GC Threads）**：V8 的垃圾回收器会尝试在后台（并发）或利用多个线程（并行）执行部分 GC 任务，减少主线程暂停（Stop-The-World）的时间。但主要的标记和清理阶段通常仍需要主线程暂停配合。
   - **关键点**：这些线程对开发者透明，旨在提升 JS 执行效率和减少主线程阻塞。

5. **Web Worker 线程（如果存在）**：
   - **非常驻**于渲染进程本身，但由渲染进程创建和管理。
   - **职责**：运行在独立线程中的 JavaScript 环境，用于执行长时间运行或计算密集型的脚本，避免阻塞主线程。
   - **通信**：通过 `postMessage` 与主线程进行通信。
   - **关键点**：开发者显式创建，用于提升复杂计算的性能和响应能力。

6. **Service Worker 线程（如果注册并激活）**：
   - 类似于 Web Worker，但主要用于网络代理、离线缓存和后台同步。
   - 运行在独立的上下文中，有自己的生命周期。
   - **关键点**：PWA 的核心技术之一，用于离线体验和后台任务。
7. 其他辅助线程
   - **定时器线程（Timer Thread）**：
     - 管理 `setTimeout`/`setInterval`，回调时通知主线程。
   - **事件线程（Event Thread）**：
     - 监听用户输入（如鼠标、键盘），分发事件到主线程。
   - **网络线程（Network Thread）**：
     - 处理子资源请求（`fetch`、`XHR`），**注意**：主网络请求可能由浏览器主进程的 **Network Service** 处理。

**总结与关键协作流程：**

1. **主线程**：处理核心渲染流水线（解析 -> 样式 -> 布局 -> 绘制记录）和 JS/事件。
2. **合成线程**：接收主线程的绘制结果（图层 + 绘制记录），分块，调度光栅化，处理滚动/动画，合成最终帧。
3. **光栅线程池**：将合成线程分发的图块光栅化成位图。交给外部的 GPU 进程。
4. **GPU 进程**：接收合成线程提交的帧（包含位图纹理和绘制指令），最终绘制到屏幕上。
5. **JS 引擎线程**（后台）：V8 内部线程加速编译和 GC。
6. **Worker 线程**（可选）：分担主线程的 JS 计算负载。

**为什么需要这么多线程？**

核心目标是**避免阻塞主线程**，实现**并行处理**，从而提升**性能**和**响应速度**。将耗时的任务（如光栅化、部分输入处理、JS 编译/GC）分流到其他线程，可以确保主线程（负责用户交互和核心渲染逻辑）尽可能快地响应用户操作，保持页面流畅（如 60fps）。

理解这些线程及其协作机制对于进行前端性能优化（如减少主线程负载、优化 JS、使用 CSS 动画替代 JS 动画、理解合成层）至关重要。
