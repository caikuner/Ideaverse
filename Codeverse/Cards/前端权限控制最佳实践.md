权限控制是前端开发中的重要环节，良好的权限控制方案应该避免大量重复的 `if/else` 或 `v-if` 判断，保持代码整洁和可维护性。以下是路由级、页面级和按钮级的权限控制最佳实践方案。

## 一、路由级权限控制

### 1. 动态路由方案（推荐）

```javascript
// 权限路由配置
const permissionRoutes = [
  {
    path: '/dashboard',
    component: Dashboard,
    meta: { permission: 'dashboard_view' }
  },
  {
    path: '/admin',
    component: Admin,
    meta: { permission: 'admin_access' }
  }
]

// 路由拦截器
router.beforeEach((to, from, next) => {
  const userPermissions = store.getters.permissions
  const requiredPermission = to.meta?.permission
  
  if (requiredPermission && !userPermissions.includes(requiredPermission)) {
    next('/forbidden') // 无权限跳转
  } else {
    next()
  }
})

// 动态添加路由
function initRoutes() {
  const userPermissions = getUserPermissions()
  const accessibleRoutes = filterRoutes(permissionRoutes, userPermissions)
  router.addRoutes(accessibleRoutes)
}
```

### 2. 按角色过滤路由

```javascript
const roleRoutes = {
  admin: ['/dashboard', '/admin', '/settings'],
  user: ['/dashboard', '/profile']
}

function filterRoutesByRole(role) {
  return routes.filter(route => roleRoutes[role].includes(route.path))
}
```

## 二、页面级权限控制

### 1. 高阶组件方案（React）

```jsx
// 权限高阶组件
function withPermission(WrappedComponent, requiredPermission) {
  return function PermissionWrapper(props) {
    const userPermissions = useSelector(state => state.user.permissions)
    
    if (!userPermissions.includes(requiredPermission)) {
      return <ForbiddenPage />
    }
    
    return <WrappedComponent {...props} />
  }
}

// 使用
const AdminPage = withPermission(AdminComponent, 'admin_access')
```

### 2. 权限提供者模式（Vue）

```javascript
// PermissionProvider.vue
<template>
  <slot v-if="hasPermission" />
  <Forbidden v-else />
</template>

<script>
export default {
  props: ['permission'],
  computed: {
    hasPermission() {
      return this.$store.getters.permissions.includes(this.permission)
    }
  }
}
</script>

// 使用
<template>
  <PermissionProvider permission="dashboard_view">
    <Dashboard />
  </PermissionProvider>
</template>
```

## 三、按钮级权限控制

### 1. 自定义指令方案（Vue）

```javascript
// 权限指令
Vue.directive('permission', {
  inserted(el, binding, vnode) {
    const userPermissions = vnode.context.$store.getters.permissions
    if (!userPermissions.includes(binding.value)) {
      el.parentNode.removeChild(el)
    }
  }
})

// 使用
<button v-permission="'user_delete'">删除用户</button>
```

### 2. 权限组件封装（React）

```jsx
// PermissionButton.jsx
function PermissionButton({ permission, children, ...props }) {
  const userPermissions = useSelector(state => state.user.permissions)
  
  if (!userPermissions.includes(permission)) {
    return null
  }
  
  return React.cloneElement(children, props)
}

// 使用
<PermissionButton permission="user_edit">
  <button>编辑用户</button>
</PermissionButton>
```

### 3. 权限 Hooks 方案（React）

```jsx
// usePermission.js
function usePermission(requiredPermission) {
  const userPermissions = useSelector(state => state.user.permissions)
  return userPermissions.includes(requiredPermission)
}

// 使用
usePermission('user_edit') && <button>编辑</button>
```

## 四、权限数据管理

### 1. 权限数据结构

```javascript
// 推荐格式
const permissions = {
  // 模块权限
  dashboard: {
    view: true,
    export: false
  },
  user: {
    create: true,
    edit: true,
    delete: false
  }
}

// 扁平化格式（适合简单系统）
const flatPermissions = [
  'dashboard.view',
  'user.view',
  'user.create',
  'user.edit'
  'user.dlete'
]
```

### 2. 权限工具函数

```javascript
// utils/permission.js
export default {
  check(permission) {
    const permissions = store.getters.permissions
    return permissions.includes(permission)
  },
  
  checkAny(permissions) {
    return permissions.some(p => this.check(p))
  },
  
  checkAll(permissions) {
    return permissions.every(p => this.check(p))
  }
}

// 使用
import permission from '@/utils/permission'

if (permission.check('user.delete')) {
  // 执行删除操作
}
```

## 五、高级优化方案

### 1. 权限指令优化（避免频繁计算）

```javascript
// 带缓存的权限指令
Vue.directive('permission', {
  inserted(el, binding) {
    const permission = binding.value
    const cacheKey = `permission_${permission}`
    
    if (!el[cacheKey]) {
      const hasPermission = store.getters.permissions.includes(permission)
      el[cacheKey] = hasPermission
      if (!hasPermission) {
        el.parentNode.removeChild(el)
      }
    }
  }
})
```

### 2. 权限组件性能优化

```jsx
// 带memo的权限组件
const PermissionComponent = React.memo(({ permission, children }) => {
  const hasPermission = usePermission(permission)
  return hasPermission ? children : null
})
```

### 3. 权限数据持久化

```javascript
// 初始化时从后端获取权限
async function initApp() {
  try {
    const permissions = await api.getUserPermissions()
    store.commit('SET_PERMISSIONS', permissions)
    initRoutes(permissions) // 动态初始化路由
  } catch (error) {
    console.error('获取权限失败', error)
  }
}
```

## 六、避免的常见问题

1. **避免硬编码权限判断**：

   ```javascript
   // 不好
   if (user.role === 'admin') { /* ... */ }
   
   // 好
   if (hasPermission('admin_access')) { /* ... */ }
   ```

2. **避免重复权限检查**：

   ```javascript
   // 不好（多个地方重复检查相同权限）
   const canEdit = permissions.includes('user_edit')
   const canDelete = permissions.includes('user_delete')
   
   // 好（集中管理）
   const { canEdit, canDelete } = useUserPermissions()
   ```

3. **避免过度细粒度控制**：
   使用 module.action 级别即可。

   ```javascript
   // 过度设计
   v-permission="'button_user_delete_confirm'"
   
   // 适度设计
   v-permission="'user_delete'"
   ```

## 总结

| 控制级别 | 推荐方案 | 优点 |
|---------|---------|------|
| 路由级 | 动态路由添加 | 彻底阻止无权限访问 |
| 页面级 | 高阶组件/权限包装组件 | 组件化，易维护 |
| 按钮级 | 自定义指令/权限组件 | 细粒度控制，声明式 |

最佳实践原则：
1. **集中管理**：权限数据统一从 store 获取
2. **声明式**：尽量使用指令或组件方式
3. **动态化**：路由和权限都应支持动态配置
4. **可维护**：避免散落的 if/else，抽象成统一方案

这样的权限控制系统既避免了代码中出现大量条件判断，又保持了良好的可维护性和扩展性。
