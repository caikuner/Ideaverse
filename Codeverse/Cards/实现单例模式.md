单例模式是一种设计模式，确保一个类**只有一个实例**，并提供**全局访问点**。

### **核心特点**

- **唯一性**：整个应用只存在一个实例。
- **全局访问**：可以从任何地方获取该实例（如 `Singleton.getInstance()`）。
- **延迟初始化**（可选）：实例在第一次访问时才创建。

|**优点**|**缺点**|
|---|---|
|节省内存（只有一个实例）|全局状态可能导致耦合度高|
|避免重复创建（如数据库连接）|难以单元测试（依赖全局状态）|
|提供统一的访问点|可能违反单一职责原则（SRP）|

### 使用场景

1. **全局状态管理**
    - 如 Redux 的 Store、Vuex 的 Store
    - 确保整个应用共享同一个状态实例。
        
2. **日志服务**
    - 单例的 Logger 可以统一管理日志输出。
        
3. **数据库连接池**
    - 避免重复创建数据库连接。
        
4. **全局配置管理**
    - 全局唯一的配置对象。
        
5. **缓存系统**
    - 如内存缓存（Redis 客户端通常也是单例）。

### **最佳实践**

- **优先依赖注入**：如果只是为了避免传递参数，可以用依赖注入代替单例。
    
- **考虑模块化**：在 Node.js/ESM 中，模块本身就是单例，无需额外实现。
    
- **仅在真正需要全局唯一性时使用**，如全局配置、共享连接池等。

---

### 实现

```js
// singleton.js
export default class Singleton {
	constructor() {
		if (!Singleton.instance) {
			Singleton.instance = this
			this.name = "Singletoon Instance"
		}
		return Singleton.instance
	}

	log() {
		console.log(this.name)
	}
}


// use case:
const instance1 = new Singleton()
const instance2 = new Singleton()
console.log(instance1 === instance2)  // true
instance1.log()
```
