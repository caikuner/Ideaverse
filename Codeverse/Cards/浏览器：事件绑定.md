> 浏览器事件处理机制不是 ES 规范，是 DOM、浏览器的实现

> 涉及面试题：事件的触发过程是怎么样的？知道什么是事件代理嘛？

## 捕获 - 目标 - 冒泡的 DOM 事件流

事件触发有三个阶段：

- 捕获阶段 (从外层往里一步步找到最内层元素)
- 目标阶段 (找到了目标元素)
- 冒泡阶段 (向上回溯，冒泡到顶层元素)

【这就是树的深度搜索呀】

不过注意，这个事件机制只是发现节点的过程，发现目标后，节点探索节点 (执行目标事件) 的顺序可不一定。

- 1.window 往目标事件触发处传播，遇到注册的捕获事件会触发
- 2.传播到事件触发处 (目标元素)，触发注册的事件
- 3.从事件触发处往 window 传播，遇到注册的冒泡事件会触发

1、3 没有疑问，遵循三个阶段的顺序。但是如果 2 中注册了多个冒泡捕获事件，是怎么个顺序呢？

- 依赖厂商的实现，看下例

## 目标阶段多个注册事件的执行顺序

### 不同级别的优先顺序

- HTML 事件、DOM0 级事件都是注册在**冒泡阶段, 且 DOM0 会覆盖掉相同的 HTML 事件**
- **addEventListener 可以注册多个，捕获、冒泡都可以**
- **如果都注册在冒泡阶段，就有执行的优先级问题：HTML 事件 = DOM0 > 冒泡阶段的 addEventListener**

**另外， addEventListener 还要区分捕获冒泡。**

### 捕获冒泡事件的顺序

**对于 DOM2 级注册事件 addEventListener，**比如给 `#div > #button` 各自都添加了 捕获阶段和冒泡阶段的两个事件，那么点击按钮 (`#button`) 时，这四个事件的执行顺序？

```
<div>
  <button>123</button>
</div>
<script>
  var btn = document.querySelector('button');
  var div = document.querySelector('div');

  btn.addEventListener('click', function () {
    console.log('bubble', 'btn');
  }, false);

  btn.addEventListener('click', function () {
    console.log('capture', 'btn');
  }, true);

  div.addEventListener('click', function () {
    console.log('bubble', 'div');
  }, false);

  div.addEventListener('click', function () {
    console.log('capture', 'div');
  }, true);
</script>

<!--
firfox 最新版v90， IE11：
capture div
bubble btn
capture btn
bubble div

chrome最新版 v90+ （89.0.4358.0+）
capture div
capture btn
bubble btn
bubble div
-->
```

事件的发现是按照 捕获 - 目标 - 冒泡当然没问题，但是执行：

- IE,Firefox(截至目前 v90),Chrome(89.0.4358.0-) 就是发现的顺序:
- 先到非目标元素 (#div) 的捕获阶段, `capture div`
- 再到目标元素 (#button)，按照具体注册的顺序来执行的！ `capture btn` `bubble btn` 谁先注册谁先执行
- 最后回到非目标元素#div 的冒泡阶段 `bubble div`

**所以，目标阶段是注册的顺序**

```
capture div
bubble btn (如果先注册冒泡事件)
capture btn
bubble div
```

- Chrome(89.0.4358.0+=) 之后，大概 2020 年底，则完全按照先捕获后冒泡的规则，与注册顺序完全无关

**所以，目标阶段，捕获的 addEventListener > HTML 事件处理程序 = DOM0 级事件处理程序 > 冒泡的 addEventListener**

```
capture div
capture btn
bubble btn
bubble div
```

## 事件处理程序

### HTML 事件处理程序

在 DOM 元素上直接绑定事件处理程序：

`<div id="test" onclick="console.log(event)"><div>`

注意，是注册在 冒泡 阶段。

### DOM0 级事件处理程序

在 JS 代码中取得元素的引用，再添加事件处理程序：

```
const el = document.getElementById('test);
el.onclick=function(){
	console.log(event)
}
```

【注意】

- 是注册在 冒泡 阶段。
- DOM0 级的缺点是，只允许注册一个事件。如果重复注册，后者覆盖前者。
- HTML 事件处理程序其实和 DOM0 差别不大，只是由于会**在 DOM 元素加载完后直接绑定** onclick，所以会最先注册。如果后面也有相同的 DOM0 级事件，也是会覆盖前者的。
- 如何移除？
  - HTML 事件程序和 DOM 级事件处理程序都可以直接把引用置为 null 来移除事件：`el.onclick = null`

### DOM2 级事件 addEventListener

我们使用 `addEventListener` 注册事件，该函数的第三个参数可以是布尔值，也可以是对象。

对于布尔值 `useCapture` 参数来说，该参数默认值为 `false` ，`useCapture` 决定了注册的事件是捕获事件还是冒泡事件。

- true: 添加到捕获阶段
- false: 添加到冒泡阶段

对于对象参数来说，可以使用以下几个属性

- `capture`：布尔值，和 `useCapture` 作用一样
- `once`：布尔值，值为 `true` 表示该回调只会调用一次，调用后会移除监听
- `passive`：布尔值，表示永远不会调用 `preventDefault`

一般来说，如果我们只希望事件只触发在目标上，这时候可以使用 `stopPropagation` 来阻止事件的进一步传播。

- **DOM2 级相比于 DOM0 的优点就是可以注册多个相同事件**。
- 重复事件一定遵循先捕获后冒泡，但是注意，在冒泡阶段注册的 HTML 事件和 DOM0 级事件优先级别更高！
- 如何移除

`**removeEventListener**`

但是注意，removeEventListener 出入的事件必须和 add 的一模一样，甚至必须是同一个对象才行：

```
const handler = function () {
    console.log('btn');
}
btn.addEventListener('click', handler, false);
btn.removeEventListener ('click', handler, false);
// 这样才能移除！！！handler对象要完全相同！


btn.addEventListener('click', function () {
    console.log('btn');
}, false);
btn.removeEventListener ('click', function () {
    console.log('btn');
}, false);
// 这样不能移除！
```

- 另外注意 标准的 addEventListener 和 IE 的 attachEvent 的区别？

### jQuery 中的事件绑定

jQuery 有两种事件绑定 api：

```js
.bind(events [,eventData], handler) // 绑定在捕获阶段

.on(events [,selector] [,data], handler) // 绑定在 冒泡阶段
```

### Vue 中的事件绑定

Vue 中的事件和原生事件有什么不同

Vue 中有两种事件绑定：

- 普通元素是原生 DOM 事件的绑定, 采用的是 `addEventListener`, 而且默认绑定在冒泡阶段，可以加 **.capture** 修饰符使它绑定在捕获阶段
- 组件绑定自定义事件采用的是事件监听 `$on` 方法
- 如果想在组件上绑定原生事件，使用 `.native` 修饰符

看这个 vue 编译器进行模板编译的例子，可以看到：

- 普通元素绑定事件的 r1 只打印了原生的 click 事件
- 组件绑定的两个事件有不同的打印

```
let compiler = require('vue-template-compiler');
let r1 = compiler.compile('<div @click="fn()"></div>');
let r2 = compiler.compile('<my-component @click.native="fn" @click="fn1"></my-component>');

console.log(r1); // {on:{click}}
console.log(r2); // {nativeOnOn:{click},on:{click}}
```

## 事件对象

#### target 和 currentTarget ❤

事件对象中比较有用的属性和方法：

- **currentTarget  ：只读属性，表示事件沿着 DOM 触发时事件的当前目标。也就是真正的目标阶段的目标元素，**总是指向事件绑定的元素**，而 Event.target 则是**事件触发的元素\*\*。
- \*\*target ：触发 事件的对象 (某个 DOM 元素) 的引用。当事件处理程序在事件的冒泡或捕获阶段被调用时，它与 `event.currentTarget` 不同。实现代理委托时显然要用 target。
- type 事件类型

#### 阻止默认行为

- `e.preventDefault()`
- 取消事件的默认行为（cancelable 属性为 true 时才可以调用）    
- 如果此事件没有被显式处理，那么它默认的动作也不要做（不设置的话默认是要做的）。
- 此事件还是继续传播，除非碰到事件侦听器调用 `[[)](18c3543fc52d79febd6016359a308b33.html|stopPropagation()]]` 或 `[[)](174458042d795962e5a2362feac06513.html|stopImmediatePropagation()]]`，才停止传播。
- `e.returnValue = false  (IE)`

#### 阻止事件传播 (冒泡捕获)

- e.stopPropagation() : 阻止捕获和冒泡阶段中当前事件的进一步传播。
- 取消所有后续事件的捕获和冒泡（bubbles 属性为 true 时才可以调用）
- 通常我们认为 `stopPropagation` 是用来阻止事件冒泡的，其实该函数也可以阻止捕获事件。
- e.cancelBubble = true (IE)

比如，页面所有按钮，如果它的 banned 属性为 true，就禁止点击（点击行为失效）,并停止传播，alert 警告信息

```
document.addEventListener('click',function(e){
  if(e.banned && e.banned===true){
    e.preventDefault();
    e.stopPropagation();
    alert('抱歉，您没有权限点击')
  }
})
```

- _event_.stopImmediatePropagation() : 阻止事件冒泡并且阻止目标注册的其他侦听器被调用。

`stopImmediatePropagation` 同样也能实现阻止事件，而且还能阻止该事件目标执行别的注册事件。

```
node.addEventListener(
  'click',
  event => {
    event.stopImmediatePropagation()
    console.log('冒泡')
  },
  false
)
// 点击 node 只会执行上面的函数，下面的函数不会执行
node.addEventListener(
  'click',
  event => {
    console.log('捕获 ')
  },
  true
)
```

## 事件代理/委托

事件代理：又称之为事件委托。把原本需要绑定在子元素的响应事件（click、keydown…）委托给父元素，让父元素担当事件监听的职务，利用事件的冒泡原理来实现的。

- 节省内存
- 不需要费心给子节点注销事件

就是说，将事件绑定在父标签上，然后点击子标签通过事件冒泡到父标签上处理。

- 比如如果一个节点中的子节点是动态生成的，那么子节点需要注册事件的话**应该注册在父节点上**
- 比如 `ul>li*10` 如果需要给 li 添加点击事件，那添加 10 个就不好了，太浪费页面性能。这时候就可以给它们的共同祖先 (比如 ul document) 添加一个监听事件 A，那么所有 li 的点击都会冒泡到这个共同祖先来执行监听事件 A。然后查看冒泡过来的事件的事件对象，就可以判断是哪个目标元素了。
- 选择 **document** 作为共同祖先比较好，因为 document 节点肯定存在，而且不需要等待页面加载就有
- 像 click mousedown mouseup keydown keypress 的事件都比较适合来做委托

```
document.addEventListener('click',function(e){
  const target = e.target;
  // target就拿到了目标元素
  if(target.tagName.toLowerCase()==='li'){
    const lilist = document.querySelectorAll('li');
    // nodelist 类数组

    const index = Array.prototype.indexOf.call(lilist,target)

    alert(`目标元素内容：${target.innerHTML}, 目标元素索引${index}`)
  }
},false)
```

## 不可冒泡事件列表

记住不可冒泡的：

```
resize error load unload mouseenter mouseleave blur focus drag 系列 media 系列 history 系列
```

H5 还定义了一些新事件：

- [[https://html.spec.whatwg.org/multipage/embedded-content.html#mediaevents]]，都不冒泡
- [[https://html.spec.whatwg.org/multipage/interaction.html#dndevents]] dragstart 、 drag 、 dragenter 、 dragexit 、 dragleave 、 dragover 、 drop 、 dragend 均冒泡
- [[https://html.spec.whatwg.org/multipage/browsers.html#history-traversal]]：popstate，hashchange 冒泡（从 window 开始…… 所以意义在哪里），pagetransition 不冒泡
