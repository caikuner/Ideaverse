> 涉及面试题：有几种方式可以实现存储功能，分别有什么优缺点？什么是 Service Worker？

目前前端可用的存储方案：
- [Web storage API](https://developer.mozilla.org/zh-CN/docs/Web/API/Web_Storage_API "DOM Storage") （localStorage，sessionStorage）
- [IndexedDB](https://developer.mozilla.org/zh-CN/docs/Web/API/IndexedDB_API) 。
- cookie 可以存储数据，但不建议（详见 [[浏览器：Cookie]]）
- service worker 可以缓存数据 （详见 [[Service Worker 缓存]]）
- URL 参数也可以携带一些不敏感数据

---

### [sessionStorage](https://developer.mozilla.org/zh-CN/docs/Web/API/Window/sessionStorage)

特点：

- 数据在页面会话结束时会被清除
- 页面会话在浏览器窗口打开期间一直保持，且**重新加载或恢复页面**仍会**保持**原来的页面会话
- 不会被共享。标签/窗口的 session 都是单独的会话，即使是相同 URL 也不会共享。

语法：

```js
// 保存数据到 sessionStorage
sessionStorage.setItem('key', 'value');

// 从 sessionStorage 获取数据
let data = sessionStorage.getItem('key');

// 从 sessionStorage 删除保存的数据
sessionStorage.removeItem('key');

// 从 sessionStorage 删除所有保存的数据
sessionStorage.clear();
```

### [localStorage](https://developer.mozilla.org/zh-CN/docs/Web/API/Window/localStorage)

特点：

- 数据可以长期保留，不会随会话结束。
- localstorage 在所有同源窗口中都是共享的

语法：

```js
localStorage.setItem('myCat', 'Tom');

let cat = localStorage.getItem('myCat');

localStorage.removeItem('myCat');

localStorage.clear();
```

### 对比：cookie，localStorage，sessionStorage，indexDB

| 特性     | **cookie**                | **localStorage**  | **sessionStorage** | **indexDB**  |
| ------ | ------------------------- | ----------------- | ------------------ | ------------ |
| 与服务端通信 | 每次都会携带在 header 中，对于请求性能影响 | 不参与               | 不参与                | 不参与          |
| 有效期    | 一般由服务器生成，可以设置过期时间         | 除非被清理，否则一直存在      | 页面关闭就清理            | 除非被清理，否则一直存在 |
| 存储大小   | 4K                        | 5M                | 5M                 | 无限           |
| 作用域    | 所有同源窗口共享                  | 所有同源窗口共享          | 不共享                |              |
| 事件通知   |                           | 数据存储触发 storage 事件 | 数据存储触发 storage 事件  |              |

- `cookie` 已经不建议用于存储。
- 一般存储使用 `localStorage` 和 `sessionStorage` 。对于不怎么改变的数据尽量使用 `localStorage` 存储，否则可以用 `sessionStorage` 存储。
