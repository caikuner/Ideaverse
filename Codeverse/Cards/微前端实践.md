微前端（Micro Frontends）是一种将前端应用拆分为独立模块的架构模式，每个模块可以独立开发、测试、部署，最终组合成一个完整的应用。以下是微前端的核心实践方案，涵盖主流技术和最佳实践：

---

## **1. 微前端核心实现方案**

### **(1) 路由分发式（Nginx/Server-Side Routing）**

- **原理**：通过服务器或反向代理（如 Nginx）根据 URL 路径路由到不同子应用。
- **适用场景**：简单架构，子应用完全独立（技术栈无关）。
- **示例**：

  ```nginx
  # Nginx 配置
  location /app1 {
    proxy_pass http://app1-server;
  }
  location /app2 {
    proxy_pass http://app2-server;
  }
  ```

### **(2) iframe 嵌套**

- **优点**：天然隔离（CSS/JS 互不干扰），快速集成。
- **缺点**：通信复杂（需 `postMessage`），SEO 不友好，性能较差。
- **示例**：

  ```html
  <iframe src="http://child-app.com" id="micro-app"></iframe>
  <script>
    document.getElementById("micro-app").contentWindow.postMessage("Hello", "*");
  </script>
  ```

### **(3) 模块联邦（Module Federation）**

- **技术**：Webpack 5+ 原生支持，动态加载远程模块。
- **优点**：共享依赖（如 React），减少重复加载。
- **配置示例**：

  ```javascript
  // host-app 的 webpack.config.js
  new ModuleFederationPlugin({
    name: "host",
    remotes: {
      childApp: "childApp@http://child-app.com/remoteEntry.js",
    },
  });
  ```

### **(4) 组合式微前端（Single-SPA / Qiankun）**

- **主流框架**：
  - **Single-SPA**：轻量级，需手动处理样式/JS 隔离。
  - **Qiankun**（基于 Single-SPA）：开箱即用的沙箱隔离、资源预加载。
- **示例（Qiankun）**：

  ```javascript
  // 主应用
  import { registerMicroApps, start } from "qiankun";
  registerMicroApps([
    {
      name: "react-app",
      entry: "//localhost:3001",
      container: "#container",
      activeRule: "/react",
    },
  ]);
  start();
  ```

## **2. 关键技术挑战与解决方案**

### **(1) 样式隔离**

| 方案                | 说明                                                                 |
|---------------------|----------------------------------------------------------------------|
| **CSS Modules**     | 子应用使用局部样式（适合 React/Vue 组件化开发）。                     |
| **Shadow DOM**      | 原生隔离（但可能影响第三方 UI 库样式）。                              |
| **Qiankun 沙箱**    | 动态加载/卸载样式表（`<style>` 标签隔离）。                           |
| **命名前缀**        | 手动添加前缀（如 `app1-btn`），适合传统项目。                         |

### **(2) JS 隔离**

| 方案                | 说明                                                                 |
|---------------------|----------------------------------------------------------------------|
| **Proxy 沙箱**      | Qiankun 使用 Proxy 劫持 `window`，实现多实例运行时隔离。              |
| **Snapshot 沙箱**   | 单实例场景下，通过快照恢复全局对象（兼容性更好）。                    |
| **iframe**          | 天然隔离，但通信成本高。                                             |

### **(3) 数据通信**

- **全局状态管理**：
  - 主应用通过 `props` 下发数据（适合父子通信）。
  - 使用 `Redux` / `Pinia` 等库，共享 Store（需约定命名空间）。
- **自定义事件**：

  ```javascript
  // 主应用
  window.dispatchEvent(new CustomEvent("global-event", { detail: data }));

  // 子应用
  window.addEventListener("global-event", (e) => console.log(e.detail));
  ```

### **(4) 公共依赖处理**

- **方案**：
  - **Webpack Module Federation**：共享 React/Vue 等库（避免重复加载）。
  - **externals**：子应用通过 `<script>` 引入 CDN 资源（需版本一致）。
- **示例（Module Federation）**：

  ```javascript
  new ModuleFederationPlugin({
    shared: {
      react: { singleton: true },
      "react-dom": { singleton: true },
    },
  });
  ```

## **3. 部署与 DevOps 实践**

### **(1) 独立部署**

- 每个子应用独立构建、部署（不同域名/CDN 路径）。
- **示例**：

  ```
  https://assets.com/app1/static/js/main.js
  https://assets.com/app2/static/js/main.js
  ```

### **(2) 主应用集成**

- **动态加载子应用**：

  ```html
  <!-- 主应用 HTML -->
  <div id="micro-app-container"></div>
  <script src="https://child-app.com/entry.js"></script>
  ```

### **(3) 版本兼容性**

- 主应用通过 **契约接口** 定义子应用规范（如生命周期钩子）：

  ```javascript
  // 子应用导出生命周期
  export const bootstrap = () => Promise.resolve();
  export const mount = (props) => render(props);
  export const unmount = () => cleanup();
  ```

## **4. 主流框架适配**

### **(1) React 子应用**

```javascript
// 子应用入口文件
import React from "react";
import ReactDOM from "react-dom";

export const mount = (container) => {
  ReactDOM.render(<App />, container);
};

// 独立运行适配
if (!window.__POWERED_BY_QIANKUN__) {
  mount(document.getElementById("root"));
}
```

### **(2) Vue 子应用**

```javascript
// 子应用入口文件
import Vue from "vue";
import App from "./App.vue";

let instance = null;

export const mount = (container) => {
  instance = new Vue({ render: (h) => h(App) }).$mount(container);
};
```

### **(3) 静态 HTML 子应用**

- 直接部署 HTML 文件，主应用通过 `fetch` 加载：

  ```javascript
  fetch("http://child-app.com/index.html")
    .then((res) => res.text())
    .then((html) => {
      document.getElementById("container").innerHTML = html;
    });
  ```

## **5. 优缺点对比**

| **方案**          | **优点**                          | **缺点**                          |
|-------------------|-----------------------------------|-----------------------------------|
| **路由分发**      | 简单，技术栈无关                  | 切换体验差，重复加载资源           |
| **iframe**        | 强隔离，快速集成                  | 通信复杂，性能差                  |
| **Module Federation** | 共享依赖，高效                | 需 Webpack 5+，配置复杂           |
| **Qiankun**       | 开箱即用，沙箱隔离                | 对非 Webpack 项目支持有限          |

---

## **6. 推荐工具链**

- **构建工具**：Webpack 5 (Module Federation)、Vite（实验性支持）。
- **框架**：Single-SPA（灵活）、Qiankun（企业级）。
- **部署**：Nginx（路由分发）、CDN（静态资源）。

---

## **总结**

- **简单场景**：路由分发或 iframe。
- **React/Vue 技术栈**：Qiankun + Module Federation。
- **高性能要求**：Webpack 模块联邦直接组合。

微前端的核心目标是 **解耦团队协作**，选择方案时需权衡 **隔离性**、**通信成本** 和 **技术栈一致性**。
