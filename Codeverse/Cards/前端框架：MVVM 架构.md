> 面试题：什么是 MVVM？比之 MVC 有什么区别？

View 和 Model：
- 视图（View）：就是用户看到的界面视图。
- 模型（Model）：数据
  
- 软件通过接口从数据库中读取数据，然后经过处理展现到用户看到的视图上。我们还可以从视图上读取用户的输入，然后又将用户的输入通过接口写入到数据库中。
- 其中，如何将数据展示到视图上，又如何将用户的输入写入到数据中。这是业务逻辑，不同的人就产生了不同的看法，从此出现了很多种架构设计。

### MVC

传统的 MVC 架构通常是使用控制器 (Controller) 更新模型，视图从模型中获取数据去渲染。当用户有输入时，会通过控制器去更新模型，并且通知视图进行更新。

![[Pasted image 20250612234837.png]]

但是 MVC 有一个巨大的缺陷就是 **控制器承担的责任太大**了，随着项目愈加复杂，控制器中的代码会越来越**臃肿**，导致出现不利于**维护**的情况。

### MVVM

> React、Vue，它们都不是严格的 MVVM 框架，只是借鉴 MVVM 的思想。

MVVM (Model-View-ViewModel) 是 MVC 的改进版，引入了 **ViewModel** 的概念。

#### Model、View、ViewModel

- Model 是**数据层**，它只关心数据本身，不关心数据如何操作和展示；
- View 是**视图层**，只负责将数据模型转化为 UI 展现给用户；
- ViewModel **为视图提供引擎**，监听模型数据的改变和控制视图⾏为、处理⽤户交互，简单理解就是⼀个同步 View 和 Model 的对象，连接 Model 和 View。它只处理数据和业务，不关心 View 如何展示数据。

![[Pasted image 20250612235000.png]]  

在这种情况下，View 和 Model 都可以独立出来，任何一方改变了也不一定需要改变另一方，并且可以将一些可复用的逻辑放在一个 ViewModel 中，让多个 View 复用这个 ViewModel。

MVVM 的目的在于更清楚地将用户界面的开发与应用程序中业务逻辑和行为的开发区分开来。因为数据驱动，一切变得更加简单。

#### 数据绑定

React/Vue 还引入了一个隐式的 Binder 层，实现了 View 和 ViewModel 的数据绑定。

传统的前端会手动操作 `dom` 元素，将数据渲染到页面上, `MVVM` 模式则是将数据**绑定**到 `viewModel` 层上，会自动将更新的数据渲染到页面视图中，也可以实现视图变化后通知 `viewModel` 层更新数据。

![[Pasted image 20250612235159.png]]

同样以 Vue 框架来举例，这个**隐式**的 Binder 层就是 Vue 通过解析模板中的插值和指令从而实现的 View 与 ViewModel 的双向数据绑定。  
React 则是指 state 的 get/set 和组件数据的绑定。


这涉及到到数据流的问题，不过对于 MVVM 来说，重要的并不是双向还是单向绑定，**而是通过 ViewModel 将视图中的状态、用户的行为分离出一个抽象，这才是 MVVM 的精髓**。

  

#### 小结

`ViewModel` 就是 `MVVM` 模式中的桥梁。

在 MVVM 架构下， View 和 Model 之间并没有直接的联系，⽽是通过 ViewModel 进⾏交互。

ViewModel 通过双向数据绑定把 View 层和 Model 层连接了起来， 因此 View 数据的变化会同步到 Model 中，⽽ Model 数据的变化也会⽴即反应到 View 上。

开 发者只需关注业务逻辑，不需要⼿动操作 DOM，不需要关注数据状态的同 步问题，复杂的数据状态维护完全由 MVVM 来统⼀管理。

  
问题是对于大型应用，数据绑定过度会导致代理的数据过多，内存消耗大。
