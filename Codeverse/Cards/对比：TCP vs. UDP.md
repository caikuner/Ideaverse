### 区别对比

**UDP（User Datagram Protocol）** 和 **TCP（Transmission Control Protocol）** 的关键区别对比：

| **对比维度**      | **UDP**                                         | **TCP**                                          |
| ----------------- | ----------------------------------------------- | ------------------------------------------------ |
| **连接方式**      | **无连接**（直接发送数据，无需握手）            | **面向连接**（需三次握手建立连接，四次挥手断开） |
| **可靠性**        | **不可靠**：不保证数据顺序、不重传丢失包        | **可靠**：通过确认、重传、排序确保数据完整       |
| **传输效率**      | **高**（无连接开销、无重传延迟）                | **较低**（需维护连接状态，有重传和流量控制开销） |
| **数据顺序**      | **不保证顺序**（数据包可能乱序到达）            | **严格有序**（通过序列号保证数据顺序）           |
| **流量控制**      | **无**（可能丢包）                              | **有**（滑动窗口机制动态调整发送速率）           |
| **拥塞控制**      | **无**（可能加剧网络拥堵）                      | **有**（慢启动、拥塞避免等算法）                 |
| **头部开销**      | **小**（8 字节：源/目标端口、长度、校验和）     | **大**（20 字节起：序列号、确认号、窗口大小等）  |
| **适用场景**      | 实时应用（视频通话、游戏、DNS、QUIC/HTTP3）     | 可靠性优先的应用（网页浏览、文件传输、邮件）     |
| **协议示例**      | DNS、DHCP、NTP、QUIC（HTTP/3）、VoIP（如 Zoom） | HTTP/1.1、HTTPS、FTP、SSH、SMTP                  |
| **多播/广播支持** | **支持**（可同时向多个目标发送数据）            | **仅支持单播**                                   |
| **安全性**        | **依赖上层协议**（如 DTLS 加密）                | **内置加密**（如 TLS/SSL）                       |

---

### **关键区别详解**

#### **1. 连接与可靠性**

- **TCP**：
  - 通过 **三次握手**（SYN, SYN-ACK, ACK）建立连接，确保双方准备好通信。
  - 通过 **确认应答（ACK）** 和 **超时重传** 保证数据可靠到达。
  - 例如：浏览网页时，TCP 确保所有数据包按顺序加载。
- **UDP**：
  - 直接发送数据包，无握手过程，适合低延迟场景。
  - 不关心数据是否到达，例如：视频通话中丢失少量帧不影响整体体验。

#### **2. 传输效率**

- **UDP**：
  - 无连接状态跟踪，头部开销小（仅 8 字节），适合高频小数据包（如游戏心跳包）。
- **TCP**：
  - 需维护连接状态和滑动窗口，头部至少 20 字节，适合大数据量传输（如文件下载）。

#### **3. 应用场景**

- **选 UDP 的情况**：
  - **实时性 > 可靠性**：在线游戏、视频会议（Zoom）、直播（RTMP）。
  - **广播/多播**：DHCP 分配 IP 地址、NTP 时间同步。
  - **自定义可靠性**：QUIC（HTTP/3）在 UDP 上实现可靠传输。
- **选 TCP 的情况**：
  - **可靠性 > 延迟**：网页加载（HTTP）、电子邮件（SMTP）、文件传输（FTP）。
  - **长连接交互**：数据库访问（MySQL）、远程登录（SSH）。

#### **4. 协议改进**

- **QUIC（基于 UDP）**：
  - 在 UDP 上实现 **可靠传输 + 多路复用 + 加密**，用于 HTTP/3，解决 TCP 队头阻塞问题。
- **WebRTC（混合使用）**：
  - 视频用 UDP（容忍丢包），信令用 TCP（保证可靠）。

---

### **总结**

- **UDP**：简单、快速、无连接，适合实时应用，但需自行处理丢包和乱序。
- **TCP**：复杂、可靠、有序，适合数据完整性优先的场景，但延迟和开销较高。

**选择建议**：

- 需要低延迟且能容忍丢包？ → **UDP**
- 需要数据 100% 完整且有序？ → **TCP**
- 想要两者优点？ → **QUIC（HTTP/3）**
