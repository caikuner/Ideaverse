`git cherry-pick` 是一个非常有用的 Git 命令，它允许你将其他分支上的特定提交 (commit) 应用到当前分支，而不是合并整个分支。

## 基本用法

```bash
git cherry-pick <提交哈希值>
```

这个命令会将指定提交的变更应用到当前分支，并创建一个新的提交。

## 主要使用场景

1. **修复 bug** - 将修复 bug 的提交单独应用到生产分支
2. **选择性合并功能** - 只合并某个功能的提交而不合并整个分支
3. **恢复丢失的提交** - 找回被错误删除的提交

## 常用选项

| 选项                  | 说明                                   |
| --------------------- | -------------------------------------- |
| `-e` 或 `--edit`      | 允许编辑提交信息                       |
| `-x`                  | 在提交信息中添加来源信息               |
| `-n` 或 `--no-commit` | 只应用变更但不提交                     |
| `-s` 或 `--signoff`   | 添加签名行                             |
| `-m parent-number`    | 对于合并提交，指定使用哪个父提交的变更 |

## 工作流程示例

1. 首先找到要应用的提交哈希：

```bash
git log 分支名
```

1. 切换到目标分支：

```bash
git checkout 目标分支
```

1. 执行 cherry-pick：

```bash
git cherry-pick abc1234
```

## 处理冲突

如果出现冲突：

1. Git 会暂停 cherry-pick 操作
2. 手动解决冲突文件
3. 使用 `git add` 标记已解决的文件
4. 继续完成操作：

```bash
git cherry-pick --continue
```

或者放弃操作：

```bash
git cherry-pick --abort
```

## 注意事项

1. 会创建新的提交记录，可能导致重复变更
2. 过度使用会使版本历史变得混乱
3. 对于需要完整合并的情况，建议使用 `git merge` 或 `git rebase`
