React 自己实现了一套事件机制，例子：

```jsx
const Test = ({ list, handleClick }) => ({
    list.map((item, index) => (
        <span onClick={handleClick} key={index}>{index}</span>
    ))
})
```

### 1.事件委托到根节点

- 点击事件 handleClick 是否绑定在了每一个标签上？
- 不是，JSX 上写的事件并没有绑定在对应的真实 DOM 上，而是通过事件代理的方式，绑定在了根节点上。这样的方式不仅减少了内存消耗，还能在组件挂载销毁时统一订阅和移除事件。
- v17 之前是绑定到 document，之后是 `ReactDOM.render` 挂载的 root 节点

### 2.合成事件代替原生 DOM 事件

冒泡到 `document` 上的事件也不是原生浏览器事件，而是 React 自己实现的合成事件（SyntheticEvent）。

实现合成事件的目的：

- 合成事件首先抹平了浏览器之间的兼容问题，这是一个跨浏览器原生事件包装器，赋予了跨浏览器开发的能力
- 对于合成事件来说，有一个事件池专门来管理它们的创建和销毁，当事件需要被使用时，就会从池子中复用对象，事件回调结束后，就会销毁事件对象上的属性，从而便于下次复用事件对象。
- 对于原生浏览器事件来说，浏览器会给监听器创建一个事件对象。如果有很多的事件监听，那么就需要分配很多的事件对象，造成高额的内存分配问题。
