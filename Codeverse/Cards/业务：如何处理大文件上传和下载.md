## 大文件上传和下载

大文件上传和下载，主要都是通过分片来优化。

切片上传

- 将大文件分割成小块
- 并发上传多个切片
- 服务端合并所有切片
- 支持断点续传和进度显示

实现步骤： 前端切片

```js
function createFileChunk(file, size = 1 * 1024 * 1024) {
  const chunks = [];
  let cur = 0;
  while (cur < file.size) {
    chunks.push(file.slice(cur, cur + size));
    cur += size;
  }
  return chunks;
}
```

上传切片

```js
async function uploadChunks(chunks) {
  const requests = chunks.map((chunk, index) => {
    const formData = new FormData();
    formData.append("chunk", chunk);
    formData.append("index", index);
    return axios.post("/upload", formData);
  });
  await Promise.all(requests);
}
```

发送合并请求

```js
await axios.post("/merge", {
  filename: file.name,
  size: chunks.length,
});
```

断点续传

- 记录已上传的切片
- 重新上传时跳过已上传的部分
- 可以通过 localStorage 存储进度
- 使用 hash 标识文件和切片

秒传

- 上传前先发送文件 hash
- 服务端存在相同文件则直接返回
- 可以使用 spark-md5 计算文件 hash

性能优化

- 并发控制：限制同时上传的切片数
- 切片大小：根据网络状况动态调整
- 进度显示：计算整体上传进度
- 错误重试：单个切片上传失败后重试

## 优化大文件上传的性能

优化大文件上传的性能需要从前端切片策略、网络传输机制、后端处理逻辑、存储效率等多个维度入手，以下是具体的优化方向和实现方法：

### **一、前端优化：切片与传输策略**

#### 1. **智能切片策略**

- **动态调整切片大小**
  - 根据文件大小自动匹配切片尺寸：
    - 小文件（<100MB）：直接上传或切分为较大切片（如 50MB/片），减少切片数量和请求次数。
    - 大文件（>1GB）：切分为较小切片（如 5MB~10MB/片），降低单请求失败风险，同时利用并行上传提升速度。
  - 公式参考：`切片大小 = max(5MB, min(文件大小 / 200, 50MB))`（平衡请求数量与单包稳定性）。
- **预加载与缓存**
  - 提前读取文件元数据（如哈希值、文件类型），减少后续重复计算。
  - 缓存已上传切片的 `ETag` 或哈希值，避免重复上传（断点续传的基础）。

#### 2. **并行上传与连接优化**

- **多线程/多通道上传**
  - 使用 `XMLHttpRequest` 或 `Fetch` 的并发请求，同时上传多个切片（需注意浏览器并发限制，通常为 6~8 个连接/域名）。
  - 示例代码（JavaScript）：

    ```javascript
    const concurrent = 4; // 并发数
    const chunks = splitFileIntoChunks(file); // 切片数组
    let uploading = 0;

    function uploadNextChunk() {
      while (uploading < concurrent && chunks.length > 0) {
        const chunk = chunks.shift();
        uploading++;
        fetch("/upload", {
          method: "POST",
          body: chunk.data,
          headers: {
            "X-Chunk-Index": chunk.index,
            "X-File-Hash": fileHash,
          },
        }).then(() => {
          uploading--;
          uploadNextChunk(); // 递归加载下一个切片
        });
      }
    }
    ```

- **长连接与 HTTP/2**
  - 启用 HTTP/2 协议，利用多路复用特性避免队头阻塞，允许单个 TCP 连接并发传输多个切片。
  - 配置服务器支持 `Keep-Alive`，减少 TCP 连接建立的开销（三次握手耗时约 200~500ms）。

#### 3. **进度监控与错误处理**

- **增量式进度更新**
  - 前端通过 `XMLHttpRequest.upload.progress` 事件实时计算已上传字节数，避免全量轮询（如每秒更新一次进度条）。
- **快速失败与重试机制**
  - 对超时或失败的切片立即重试（如设置 3 次重试间隔，每次间隔递增：1s→3s→5s），避免阻塞后续切片上传。
  - 使用 `AbortController` 取消长时间未响应的请求，释放资源。

### **二、网络层优化：协议与传输加速**

#### 1. **CDN 加速与边缘节点**

- 将上传流量分发到离用户更近的 CDN 边缘节点，减少源站距离带来的延迟（如阿里云 OSS、腾讯云 COS 均支持分片上传 +CDN 加速）。
- 示例场景：用户在上海上传文件，通过 CDN 边缘节点（上海机房）直接写入就近的存储集群，而非回源到北京源站。

#### 2. **QUIC 协议与 UDP 传输**

- 采用基于 UDP 的 QUIC 协议（如 HTTP/3），减少 TCP 握手延迟和拥塞控制带来的吞吐量限制，尤其适合高丢包率网络（如移动网络）。
- 部分云服务商（如 Cloudflare）已支持 QUIC 加速，可显著提升大文件上传速度。

#### 3. **压缩与数据去重**

- **切片级压缩**
  - 对文本类文件（如日志、代码）的切片进行实时压缩（如 gzip/brotli），减少传输字节数。
  - 注意：二进制文件（如视频、图片）压缩收益较低，可能增加 CPU 开销，需谨慎启用。
- **内容哈希去重**
  - 服务端维护已上传切片的哈希表，若检测到重复切片（如同一用户多次上传相同文件），直接复用已有切片，跳过传输。

### **三、后端优化：处理与存储效率**

#### 1. **切片接收与并行合并**

- **异步队列处理**
  - 使用消息队列（如 RabbitMQ、Kafka）解耦上传接收与文件合并，避免前端等待合并完成（适用于非实时场景）。
  - 示例流程：
    1. 前端上传切片→服务端接收并存储切片→写入队列通知合并。
    2. 独立的合并服务从队列中拉取任务，按顺序拼接文件→生成最终文件。
- **并行合并线程**
  - 对大文件采用多线程合并（如按切片索引分块写入文件），利用多核 CPU 加速拼接（需注意文件锁竞争问题）。

#### 2. **存储系统优化**

- **分布式存储与 RAID**
  - 使用分布式文件系统（如 HDFS、Ceph）或对象存储（如 S3、OSS），利用多副本和条带化提升写入速度。
  - 对本地存储启用 RAID 0 或 NVMe SSD，减少 I/O 瓶颈（尤其适用于单机高并发上传场景）。
- **冷热数据分离**
  - 将高频上传的临时切片存储在高性能缓存（如 Redis+SSD），合并后的文件迁移至低成本存储（如 HDD 或归档存储）。

#### 3. **限流与优先级队列**

- **基于 Token 的上传限流**
  - 限制单个用户或 IP 的并发上传连接数（如最多同时上传 10 个切片），避免耗尽服务器资源。
- **优先级队列**
  - 为企业用户或 VIP 用户分配更高的上传带宽优先级，通过 QoS（服务质量）策略保障关键流量。

### **四、其他优化方向**

#### 1. **硬件与基础设施**

- 升级服务器至万兆网卡，降低网络带宽瓶颈。
- 使用 GPU 加速哈希计算（如 CUDA 加速 SHA-256），减少大文件完整性校验时间。

#### 2. **用户体验增强**

- **上传预检测**
  - 前端提前校验文件类型、大小，并计算哈希值，避免无效上传（如用户上传一个 2GB 的非视频文件）。
- **断点续传可视化**
  - 在界面显示已上传切片和待上传切片，允许用户手动跳过或重新上传特定切片。

#### 3. **监控与日志**

- 全链路监控上传延迟、成功率、切片丢失率等指标，及时发现网络瓶颈或服务端故障。
- 记录每个切片的上传时间戳和 IP 地址，用于溯源和故障排查。

### **优化效果对比参考**

| 优化策略                  | 小文件（50MB）上传耗时 | 大文件（10GB）上传耗时   |
| ------------------------- | ---------------------- | ------------------------ |
| 普通单线程上传            | 约 15 秒               | 约 45 分钟（易失败）     |
| 切片 + 并行上传（4 线程） | 约 8 秒                | 约 25 分钟（失败率↓80%） |
| 切片 +CDN+QUIC            | 约 5 秒                | 约 18 分钟（延迟↓40%）   |
| 全链路优化（含存储加速）  | 约 3 秒                | 约 12 分钟               |

### **总结**

大文件上传性能优化的核心是**分而治之**：通过切片将大任务拆解为小单元，利用并行处理和现代网络协议提升吞吐量，同时通过缓存、去重和存储优化减少无效开销。实际应用中需结合业务场景选择优先级，例如：

- **高频小文件**：侧重 CDN 加速和连接复用。
- **超大文件（>10GB）**：优先实现动态切片、断点续传和分布式存储合并。
- **弱网环境**：启用 QUIC 协议、切片重试策略和流量压缩。
