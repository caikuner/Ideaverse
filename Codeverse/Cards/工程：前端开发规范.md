前端开发规范是确保代码质量、团队协作效率和项目可维护性的重要基础，通常涵盖以下核心方面：

---

### 一、**代码风格规范**

1. **缩进与换行**
   - 统一使用空格（2/4 个）或制表符
   - 文件末尾保留空行

   ```javascript
   // 示例：2空格缩进
   function demo() {
     if (true) {
       console.log("Hello");
     }
   }
   ```

2. **命名约定**
   - 变量/函数：`camelCase`（如 `userName`）
   - 类名/构造函数：`PascalCase`（如 `UserModel`）
   - 常量：`UPPER_CASE`（如 `API_ENDPOINT`）
   - CSS 类名：`kebab-case`（如 `.main-container`）

3. **引号与分号**
   - 统一单引号/双引号（推荐单引号）
   - 分号是否强制（推荐保留）

---

### 二、**技术栈规范**

1. **框架选择**
   - 明确使用 React/Vue/Angular 及其版本
   - 配套状态管理工具（Redux/Pinia/RxJS）

2. **CSS 方案**
   - 原子化（Tailwind/UnoCSS）
   - CSS Modules/Sass/Less
   - 作用域隔离方案（Vue Scoped CSS）

3. **构建工具**
   - Vite/Webpack 配置标准
   - 分包策略（`splitChunks` 规则）

---

### 三、**工程化规范**

1. **目录结构**

   ```markdown
   src/
   ├── assets/ # 静态资源
   ├── components/ # 公共组件
   ├── hooks/ # 自定义Hook
   ├── store/ # 状态管理
   ├── utils/ # 工具函数
   └── views/ # 页面组件
   ```

2. **Git 工作流**
   - 分支命名（`feature/xxx`、`fix/xxx`）
   - Commit 消息格式（Angular 规范）：

     ```
     feat: 添加用户登录功能
     fix(router): 修复路由跳转闪屏问题
     ```

3. **代码提交前检查**
   - ESLint + Prettier 自动格式化
   - Husky + lint-staged 钩子校验

   ```json
   // package.json 示例
   "lint-staged": {
     "*.{js,ts,vue}": ["eslint --fix", "prettier --write"]
   }
   ```

---

### 四、**组件开发规范**

1. **组件设计原则**
   - 单一职责（一个组件只做一件事）
   - 受控 vs 非受控组件选择
   - Props 类型校验（TypeScript/PropTypes）

2. **Vue 组件示例**

   ```vue
   <template>
     <button :class="['btn', `btn-${type}`]" @click="handleClick">
       <slot></slot>
     </button>
   </template>

   <script setup>
   defineProps({
     type: {
       type: String,
       default: "primary",
       validator: (v) => ["primary", "danger"].includes(v),
     },
   });
   </script>
   ```

3. **React 最佳实践**
   - Hooks 使用顺序规范
   - 避免在渲染函数内定义函数

   ```tsx
   // 推荐 useCallback 优化
   const handleClick = useCallback(() => {
     setCount((prev) => prev + 1);
   }, []);
   ```

---

### 五、**性能与安全**

1. **优化要求**
   - 图片懒加载（`loading="lazy"`）
   - 组件异步加载（`React.lazy`/`defineAsyncComponent`）
   - 虚拟列表（长列表渲染）

2. **安全规范**
   - 禁止 `innerHTML` 直接渲染用户输入
   - API 请求参数过滤（防 XSS/SQL 注入）
   - CSP 内容安全策略配置

---

### 六、**文档与协作**

1. **注释标准**
   - JSDoc 函数注释

   ```javascript
   /**
    * 计算两数之和
    * @param {number} a - 第一个加数
    * @param {number} b - 第二个加数
    * @returns {number} 相加结果
    */
   function sum(a, b) {
     return a + b;
   }
   ```

2. **README 必备内容**
   - 项目启动命令
   - 环境变量配置
   - 重要依赖版本

---

### 七、**测试规范**

1. **测试覆盖率要求**
   - 工具：Jest/Vitest + Testing Library
   - 核心组件/工具函数 100% 覆盖率

2. **测试用例结构**

   ```javascript
   describe("sum function", () => {
     it("should return 3 when adding 1 and 2", () => {
       expect(sum(1, 2)).toBe(3);
     });
   });
   ```

---

### 八、**跨端兼容性**

1. **浏览器支持策略**
   - 明确支持的最低版本（如 Chrome >= 90）
   - Polyfill 引入规则（通过 `browserslist` 控制）

2. **移动端适配**
   - REM/POSTCSS-PXTOVIEWPORT 方案选择
   - 1px 边框问题解决方案

---

通过制定并遵守这些规范，团队可以实现：  
✅ 代码风格统一  
✅ 减少低级错误  
✅ 提升协作效率  
✅ 降低维护成本

建议结合项目实际情况选择性采用，并通过自动化工具（如 ESLint 插件）强制执行关键规则。
