## 浏览器事件循环机制

浏览器的事件循环由 **HTML5 规范** 定义，主要分为 **宏任务（Macrotask）** 和 **微任务（Microtask）** 两类任务队列。
如需更深入细节，可参考 [[https://html.spec.whatwg.org/multipage/webappapis.html#event-loops]]。

### **执行流程**

![[EventLoop 20250615151341.png]]

1. **执行栈（Call Stack）**
   - 同步代码按顺序执行，遇到异步任务（如 `setTimeout`、`fetch`）时，交给 **Web API** 处理。
   - 异步任务完成后，回调函数进入 **任务队列（Task Queue）**。
2. **微任务（Microtask）优先**
   - 每次 **宏任务（如 `script`、`setTimeout`）** 执行完毕后，立即清空 **微任务队列**（如 `Promise.then`、`MutationObserver`）。
   - 微任务执行期间如果产生了新的微任务，会加入当前微任务队列的**末尾**，**继续执行清空**
3. **渲染（Render）阶段（可选）**
   - 浏览器可能选择在事件循环的某个时机进行 **UI 渲染**（如 `requestAnimationFrame`），但并非每次循环都会渲染。

4. **下一轮事件循环**
   - 从 **宏任务队列** 取出**下一个**任务执行（如 `setTimeout` 回调），重复上述过程。

### **宏微任务及执行时机**

| **任务类型** | **示例**                                                                   | **执行时机**               |
| ------------ | -------------------------------------------------------------------------- | -------------------------- |
| **宏任务**   | `setTimeout`、`setInterval`、<br>`I/O`、`UI 渲染`、`requestAnimationFrame` | 每次事件循环取**一个**执行 |
| **微任务**   | `Promise.then`、await、<br>`MutationObserver`、`queueMicrotask`            | 该宏任务执行后立即全部清空 |

### 示例

```js
console.log("script start"); // 同步任务

setTimeout(() => console.log("setTimeout"), 0); // 宏任务

Promise.resolve().then(() => {
  console.log("Promise");
  Promise.resolve().then(() => {
    console.log("微任务产生的微任务");
  });
}); // 微任务

console.log("script end"); // 同步任务
```


## 浏览器 vs. Node.js 事件循环对比

[[Node.js：事件循环机制]]

| **特性**           | **浏览器**                          | **Node.js（最新版）**            |
| ------------------ | ----------------------------------- | -------------------------------- |
| **任务队列结构**   | 宏任务 + 微任务                     | 6 阶段（Timers、Poll、Check 等） |
| **微任务执行时机** | 每个宏任务后立即执行                | 每个阶段结束后执行               |
| `setImmediate`     | ❌ 仅 IE 支持                       | ✅ 在 Check 阶段执行             |
| `process.nextTick` | ❌ 不存在                           | ✅ 微任务之前执行（最高优先级）  |
| **I/O 处理**       | 依赖 Web API（如 `fetch`）          | 基于 libuv（非阻塞 I/O）         |
| **渲染阶段**       | ✅ 可能执行 `requestAnimationFrame` | ❌ 无 UI 渲染                    |
| **典型任务**       | `setTimeout`、`DOM 事件`            | `fs.readFile`、`http` 请求       |

### **关键差异**

1. **微任务执行时机**
   - **浏览器**：每**个**宏任务后立即执行微任务。
   - **Node.js v11+**：每个阶段（如 Timers、Poll）结束后执行微任务（与浏览器对齐）。

2. **`setTimeout` vs. `setImmediate`**
   - **浏览器**：`setImmediate` 仅 IE 支持，通常用 `setTimeout(fn, 0)` 替代。
   - **Node.js**：`setImmediate` 在 **Check 阶段** 执行，通常比 `setTimeout(fn, 0)` 更快。

3. **`process.nextTick`**
   - Node.js 特有，优先级高于 `Promise.then`，用于 **立即异步执行**（如事件触发前处理数据）。

---

### **小结**

- **浏览器**：
  - 基于 **宏任务 + 微任务**，每次循环执行一个宏任务并清空微任务。
  - **UI 渲染可能穿插** 在事件循环中。
- **Node.js（v11+）**：
  - 采用 **6 阶段模型**，每个阶段结束后清空微任务（与浏览器一致）。
  - **`process.nextTick` 优先级最高**，适合高实时性任务。
  - **`setImmediate` 用于替代 `setTimeout(fn, 0)`**，确保更快执行。

**适用场景**：

- **浏览器**：处理 DOM 交互、动画、网络请求。
- **Node.js**：高并发 I/O（如服务器、文件操作）。
