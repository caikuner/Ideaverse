## 1. 进程与线程

### 进程 (Process)

- **定义**：操作系统资源分配的基本单位，是程序的**一次执行实例**
- **特点**：
  - 拥有独立的地址空间、内存、数据栈等
  - 进程间相互隔离，一个进程崩溃不会影响其他进程
  - 创建/销毁进程开销较大（需要分配/回收系统资源）
  - 进程间通信 (IPC) 需要特殊机制（管道、消息队列等）

### 线程 (Thread)

- **定义**：CPU 调度的基本单位，是**进程内的一个执行流**
- **特点**：
  - 共享进程的内存空间和资源
  - 创建/销毁开销小，切换速度快
  - 线程间通信简单（可直接读写共享内存）
  - 一个线程崩溃可能导致整个进程崩溃

### 进程 vs 线程对比

| 特性        | 进程                      | 线程                      |
|------------|--------------------------|--------------------------|
| 资源占用    | 多（独立内存空间）         | 少（共享进程资源）         |
| 创建/销毁   | 开销大                    | 开销小                   |
| 通信方式    | 复杂（需要 IPC 机制）        | 简单（共享内存）          |
| 稳定性      | 高（相互隔离）             | 低（一个线程崩溃可能影响整个进程）|
| 并发性      | 进程间并发                 | 线程间并发                |

## 2. 死锁 (Deadlock)

### 死锁定义

多个进程/线程因**竞争资源**而造成的一种互相等待的现象，若无外力作用，这些进程/线程都将无法继续执行。

### 死锁产生的四个必要条件（全部满足才会死锁）

1. **互斥条件**：资源一次只能被一个进程/线程占用
2. **占有并等待**：进程持有资源并等待获取其他资源
3. **非抢占条件**：已分配的资源不能被其他进程强行夺取
4. **循环等待条件**：存在一个进程/线程的循环等待链

### 死锁示例（代码）

```java
// 两个线程互相等待对方释放锁
public class DeadlockExample {
    private static final Object lock1 = new Object();
    private static final Object lock2 = new Object();

    public static void main(String[] args) {
        Thread thread1 = new Thread(() -> {
            synchronized (lock1) {
                System.out.println("Thread1 holds lock1");
                try { Thread.sleep(100); } catch (InterruptedException e) {}
                synchronized (lock2) {
                    System.out.println("Thread1 holds lock2");
                }
            }
        });

        Thread thread2 = new Thread(() -> {
            synchronized (lock2) {
                System.out.println("Thread2 holds lock2");
                synchronized (lock1) {
                    System.out.println("Thread2 holds lock1");
                }
            }
        });

        thread1.start();
        thread2.start();
    }
}
```

### 死锁处理策略

1. **预防**：破坏四个必要条件中的至少一个
   - 破坏互斥：某些资源改为共享（不总是可行）
   - 破坏占有并等待：一次性申请所有资源
   - 破坏非抢占：允许抢占资源
   - 破坏循环等待：按固定顺序申请资源

2. **避免**：银行家算法等动态检查资源分配状态
3. **检测与恢复**：允许死锁发生，定期检测并恢复
4. **忽略**：如 Unix/Linux 等系统对死锁采取忽略策略

## 3. 进程间通信 (IPC)

### 主要 IPC 方式

1. **管道 (Pipe)**
   - 单向通信，先进先出
   - 匿名管道：父子进程间使用
   - 命名管道 (FIFO)：无关进程间使用

2. **消息队列 (Message Queue)**
   - 消息的链表，存储在内核中
   - 可以按类型读取消息

3. **共享内存 (Shared Memory)**
   - 最高效的 IPC 方式
   - 多个进程映射同一块内存区域
   - 需要同步机制（如信号量）配合

4. **信号量 (Semaphore)**
   - 用于进程间同步
   - 计数器，控制多个进程对共享资源的访问

5. **信号 (Signal)**
   - 用于通知进程某事件已发生
   - 如 kill 命令发送信号

6. **套接字 (Socket)**
   - 可用于不同主机间的进程通信
   - 也支持同一主机的进程通信

### 示例：共享内存（C 语言）

```c
#include <sys/ipc.h>
#include <sys/shm.h>
#include <stdio.h>

int main() {
    // 创建共享内存段
    int shmid = shmget(IPC_PRIVATE, 1024, 0666|IPC_CREAT);
    
    // 附加到进程地址空间
    char *shm = (char*)shmat(shmid, NULL, 0);
    
    // 写入数据
    sprintf(shm, "Hello Shared Memory!");
    
    // 读取数据
    printf("Data read from shared memory: %s\n", shm);
    
    // 分离共享内存
    shmdt(shm);
    
    // 删除共享内存
    shmctl(shmid, IPC_RMID, NULL);
    
    return 0;
}
```

## 4. 线程间通信

由于线程共享进程资源，通信方式比进程简单：

1. **共享变量**
   - 最简单的通信方式
   - 需要同步机制保证线程安全

2. **互斥锁 (Mutex)**
   - 保护共享资源，防止竞态条件

3. **条件变量 (Condition Variable)**
   - 用于线程间状态通知
   - 常与互斥锁配合使用

4. **信号量 (Semaphore)**
   - 控制对共享资源的访问数量

5. **屏障 (Barrier)**
   - 同步多个线程，等待所有线程到达某点后再继续

### 示例：生产者 - 消费者问题（Java）

```java
import java.util.LinkedList;
import java.util.Queue;

public class ProducerConsumer {
    private static final int CAPACITY = 5;
    private final Queue<Integer> queue = new LinkedList<>();
    private final Object lock = new Object();

    public void produce() throws InterruptedException {
        int value = 0;
        while (true) {
            synchronized (lock) {
                while (queue.size() == CAPACITY) {
                    lock.wait(); // 队列满，等待
                }
                queue.add(value);
                System.out.println("Produced: " + value);
                value++;
                lock.notifyAll(); // 通知消费者
            }
            Thread.sleep(1000);
        }
    }

    public void consume() throws InterruptedException {
        while (true) {
            synchronized (lock) {
                while (queue.isEmpty()) {
                    lock.wait(); // 队列空，等待
                }
                int value = queue.poll();
                System.out.println("Consumed: " + value);
                lock.notifyAll(); // 通知生产者
            }
            Thread.sleep(1000);
        }
    }

    public static void main(String[] args) {
        ProducerConsumer pc = new ProducerConsumer();
        Thread producer = new Thread(() -> {
            try { pc.produce(); } 
            catch (InterruptedException e) { e.printStackTrace(); }
        });
        Thread consumer = new Thread(() -> {
            try { pc.consume(); } 
            catch (InterruptedException e) { e.printStackTrace(); }
        });
        producer.start();
        consumer.start();
    }
}
```

## 5. 关键总结

1. **选择进程还是线程**：
   - 需要安全隔离 → 进程
   - 需要高效共享 → 线程

2. **避免死锁**：
   - 按固定顺序获取锁
   - 使用超时机制
   - 避免嵌套锁

3. **通信方式选择**：
   - 进程间：根据性能需求选择（共享内存最快）
   - 线程间：优先使用共享内存 + 同步机制

4. **同步是关键**：
   - 任何共享资源的访问都需要同步
   - 正确使用锁、信号量等同步原语

理解这些概念对于开发高效、稳定的并发程序至关重要。实际开发中应根据具体场景选择合适的并发模型和通信机制。
