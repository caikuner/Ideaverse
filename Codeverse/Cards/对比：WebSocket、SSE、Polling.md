### **核心特性对比**

| **特性**           | **WebSocket**                       | **SSE (Server-Sent Events)**                 | **Polling (轮询)**         |
| ------------------ | ----------------------------------- | -------------------------------------------- | -------------------------- |
| **协议**           | 独立协议（基于 TCP，HTTP 升级握手） | HTTP（长连接）                               | HTTP（短连接）             |
| **通信方向**       | 全双工（双向通信）                  | 单工（仅服务端→客户端）                      | 半双工（客户端主动请求）   |
| **实时性**         | 极高（毫秒级延迟）                  | 高（服务端可主动推送）                       | 低（依赖轮询间隔）         |
| **数据格式**       | 二进制帧或文本帧                    | 纯文本（`text/event-stream`）                | 任意（JSON/XML 等）        |
| **连接开销**       | 1 个持久化 TCP 连接                 | 1 个持久化 HTTP 连接                         | 频繁的 TCP 连接建立/关闭   |
| 自动重连           | ❌ 需手动实现                       | ✅ 内置支持                                  | ❌ 无                      |
| **服务端推送支持** | ✅ 是                               | ✅ 是                                        | ❌ 否（需客户端主动请求）  |
| **浏览器兼容性**   | 所有现代浏览器                      | 除 IE/Edge 外的主流浏览器                    | 所有浏览器                 |
| 基础设施           | 不支持 HTTP 缓存、CDN 等基础设施    | ✅                                           | ✅                         |
| **典型应用场景**   | 聊天、在线游戏、实时协作            | 服务端主导的推送，如 股票行情、日志、AI 对话 | 简单数据更新（如天气查询） |

---

### **性能对比**

| **指标**       | **WebSocket**       | **SSE**             | **短轮询**         | **长轮询**     |
| -------------- | ------------------- | ------------------- | ------------------ | -------------- |
| **延迟**       | 极低（实时）        | 低（≈100ms）        | 高（依赖间隔）     | 中等（≈1s）    |
| **带宽开销**   | 低（无重复头部）    | 低（长连接）        | 高（重复头部）     | 中等           |
| **服务端压力** | 低（1 连接/客户端） | 低（1 连接/客户端） | 高（频繁连接）     | 中（连接挂起） |
| **CPU 占用**   | 低（事件驱动）      | 低                  | 高（频繁处理请求） | 中             |

### **选型建议**

- **选择 WebSocket 当**：
  - 需要双向实时通信（如聊天、游戏）。
  - 高频交互且对延迟敏感。
- **选择 SSE 当**：
  - 只需服务端推送（如新闻、股价）。
  - 希望利用 HTTP 现有基础设施。
- **选择 Polling 当**：
  - 兼容性要求极高（支持 IE）。
  - 数据更新频率低（如每分钟 1 次）。

---

### **总结**

- **实时性**：WebSocket > SSE > 长轮询 > 短轮询。
- **兼容性**：Polling > WebSocket ≈ SSE。
- **资源消耗**：短轮询 > 长轮询 > WebSocket > SSE 。
- **选择时需权衡**：实时性需求、浏览器兼容性、服务端架构。
