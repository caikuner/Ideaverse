> Q: 后端返回 10w 条数据，直接在前端全部加载和渲染会导致内存占用高、页面卡顿、响应缓慢，前端该如何处理？

针对长列表（如 1 万条以上数据）的渲染性能问题，业界主流优化方案可分为 **虚拟化渲染**、**分片加载** 和 **GPU 加速** 三大方向。还有一些其他的优化手段如下

### 1. 服务器端分页和过滤

- **服务器端分页：**
  - 最理想的方法是让后端只返回当前页面所需的数据，通过接口传递分页参数（例如 page 和 limit）。这样既可以后端减少查询数据，前端也处理少量数据，减轻渲染压力。
- **服务器端过滤和排序：**
  - 在后端做数据筛选，只返回满足条件的数据，进一步减少前端接收的数据量。

### 2. 虚拟列表（Virtual List）/ 懒加载（Lazy Loading）

仅渲染可视区域内的元素，动态替换内容，减少 DOM 节点数量。

#### (1) 定高虚拟列表

- **适用场景**：列表项高度固定。
- **实现库**：
  - React: `react-window`、`react-virtualized`
  - Vue: `vue-virtual-scroller`
- **示例代码（React）**：

  ```jsx
  import { FixedSizeList } from "react-window";

  const Row = ({ index, style }) => <div style={style}>Row {index}</div>;

  const VirtualList = () => (
    <FixedSizeList
      height={400}
      itemCount={10000}
      itemSize={50} // 固定高度
      width={300}
    >
      {Row}
    </FixedSizeList>
  );
  ```

#### (2) 不定高虚拟列表

- **适用场景**：列表项高度动态变化。
- **实现库**：
  - React: `react-virtuoso`、`react-window`（搭配 `useDynamicSize`）
  - Vue: `vue-virtual-scroll-list`
- **优化技巧**：
  - 预估初始高度，滚动时动态测量并缓存。
  - 使用 `ResizeObserver` 监听高度变化。

### 3. 分批分片加载（Chunk Rendering）

将数据分为小批次，逐步渲染到页面上，从而分摊渲染开销，避免一次性渲染处理全部数据阻塞主线程，保持 UI 流畅。其中，要选择触发每个批次渲染的时机：（结合事件循环机制）

- 选择 requestAnimationFrame，这样是正常在下一次重绘前触发
- 选择 requestIdleCallback，这样是在浏览器空闲时触发 （react）
- 选择定时任务，定期触发
- 也可以采用主动触发，比如监听鼠标滚动事件，触发下一片数据

另外，`document.createDocumentFragment` 可以生成代码片段，一次性插入 dom，避免每个项都进行一次 dom 操作。

> [[chunkRenderWithRIC.js]] [[chunkRenderWithRAF.js]]

#### **(1) 时间分片（Time Slicing）**

- **技术**：`requestAnimationFrame`、 `requestIdleCallback` 或 `setTimeout` 分批渲染。
- **示例代码**：
  - react 就是这种方式 [[React：Concurrency 并发机制#1. Fiber 架构 + 时间切片（Time Slicing）]]

  ```javascript
  async function renderChunk(list, chunkSize = 50) {
    for (let i = 0; i < list.length; i += chunkSize) {
      await new Promise((resolve) =>
        requestIdleCallback(() => {
          renderItems(list.slice(i, i + chunkSize));
          resolve();
        }),
      );
    }
  }
  ```

#### (2) 滚动加载（Infinite Scroll）

- **技术**：监听滚动事件，触发加载下一页数据。
- **实现库**：
  - React: `react-infinite-scroller`
  - Vue: `vue-infinite-loading`

### 4. GPU 加速渲染

利用 CSS `transform` 和 `will-change` 启用 GPU 加速，减少重排/重绘。

- **绝对定位 + transform**：

  ```css
  .list-item {
    position: absolute;
    transform: translateY(var(--top));
    will-change: transform; /* 提示浏览器优化 */
  }
  ```

- **避免使用 `top/left`**：这些属性会触发重排，而 `transform` 不会。

### 5. 数据处理优化

1. 异步数据处理
   如果有一些复杂计算，可以使用 Web Worker 将计算放到后台线程，避免阻塞主线程。
2. **数据缓存：**
   对于已加载的数据可以使用内存缓存或者 IndexedDB 缓存，避免重复请求，提升用户体验。
3. 数据扁平化
   - 避免嵌套过深的数据结构，减少渲染时的递归开销。
4. 惰性计算
   - 只在需要时计算列表项的可见性（如滚动时动态判断）。

### 6. 框架级优化

#### **(1) React 优化**

- **避免不必要的重新渲染**：
  - 使用 `React.memo` 或 `useMemo` 缓存组件。
  - 确保 `key` 稳定，避免列表项全部重建。
- **并发模式（Concurrent Mode）**：
  - 使用 `useTransition` 降低渲染优先级，避免卡顿。

#### **(2) Vue 优化**

- **v-for 优化**：

  ```html
  <template v-for="item in list" :key="item.id">
    <!-- 绑定稳定的 key -->
  </template>
  ```

- **使用 `v-memo`**（Vue 3.2+）：

  ```html
  <div v-for="item in list" v-memo="[item.id]">
    <!-- 仅当 item.id 变化时重新渲染 -->
  </div>
  ```

### 7. 终极方案：WebAssembly + Canvas

- 超大数据量（如 10 万 + 条）且需要复杂交互。
- **技术栈**：
  - 使用 Rust/C++ 编写计算逻辑，编译为 WebAssembly。
  - 通过 Canvas 或 WebGL 直接绘制列表，完全绕过 DOM。

**案例**

- **Figma**：使用 WebAssembly + Canvas 渲染复杂设计稿。
- **Google Sheets**：虚拟化渲染百万级单元格。

---

### 最佳实践

1. **优先推动后端分页**（从源头解决问题）。
2. **必须全量加载时**：
   - **首推虚拟列表**（`react-window`/`vue-virtual-scroller`）。
   - **动态高度列表**优先选择 `react-virtuoso` 或 `vue-virtual-scroll-list`。
   - 动态计算 → Web Worker + 分片渲染。
3. **缓存高频访问数据**，减少重复请求。
4. **超高性能需求**考虑 WebAssembly + Canvas 方案。
