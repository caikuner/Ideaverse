> Q: Taro/Uniapp 的差量更新机制

#### **1. 核心原理**

差量更新（Delta Update）通过 **对比新旧版本文件**，仅下载并更新**发生变动的部分**，而非全量包，显著降低更新体积和耗时。其技术实现分为三步：

- **版本比对**：构建时生成文件哈希（如 MD5），与线上版本对比差异。
- **增量包生成**：打包工具（如 Taro CLI）提取差异文件，压缩为增量补丁。
- **客户端热更新**：应用运行时拉取增量包，动态合并到本地代码。

#### **2. 实现方案对比**

| **框架**   | **技术方案**                               | **适用场景**                    |
| ---------- | ------------------------------------------ | ------------------------------- |
| **Taro**   | 基于 `taro build --incremental` 生成差量包 | React/Vue 跨端项目（小程序/H5） |
| **Uniapp** | 依托 `wgt` 热更新包（官方更新中心）        | 全端兼容（小程序/App/快应用）   |

#### **3. 操作流程（以 Taro 为例）**

1. **配置差量构建**：

   ```bash
   # 生成带哈希的 manifest 文件
   taro build --type weapp --incremental
   ```

2. **部署差量包**：
   - 将 `dist` 中的 `__chunks__`（差异文件）上传至 CDN。
3. **客户端更新**：

   ```javascript
   // 检查并应用更新
   Taro.downloadUpdate({
     url: "https://cdn.com/patch-1.0.1.zip",
     success: () => Taro.applyUpdate(),
   });
   ```

#### **4. 性能收益**

- **更新体积**：从全量 2MB 降至 50KB（仅修改 1 个文件时）。
- **更新速度**：下载时间从 10s 缩短至 1s（弱网环境优势明显）。
- **成功率**：避免大包下载超时，更新成功率提升 30%+。

#### **5. 注意事项**

- **版本兼容性**：差量更新需确保新旧版本基础代码结构一致。
- **回滚机制**：更新失败时自动回退到完整包下载。
- **安全校验**：增量包需签名防篡改（如 Taro 的 `verifyUpdate` 钩子）。

#### **6. 适用场景**

- **高频迭代**：适合日更/周更的运营活动页。
- **大体积应用**：初始包超 2MB 的小程序或 Hybrid App。
- **弱网环境**：用户网络条件较差时保障更新体验。

通过差量更新，Taro/Uniapp 可实现 **静默无感更新**，用户无感知完成版本升级。
