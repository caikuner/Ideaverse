1. record.conf 中 view_level 的 click_level 什么意思

维度级别：点击级别。点击日志里都是 click_level，检索日志是 pv_level ad_level。
使用在 多层日志：检索日志里面，一个 PV 一条日志（这是 pv_level），一个 PV 里有多个广告（这是 ad_level）。

1. baiduid 新鲜度是特征吗？是写在 feature.conf 里面的特征吗？

可以算是广义的特征，是前端的页面行为记录，有一定的作弊识别作用，我们可以从日志中直接拿来用作特征值。但不是我们业务里 feature.conf 配置的 feature。

1. care_tag 是什么？怎么配置的？

可以用 care_tag 来标志 长的 care 表达式组合，比如：`@care_tag:[#PC]=['is_wiseless':=0]`
配置在 feature.conf 中，后面一旦遇到#PC 这个 tag，会自动转成后面的表达式。
系统有专门的页面来管理可用的 care_tag。由于 feature-lib 处理 care_tag 有额外性能损耗，目前不直接写入 feature.conf，只在平台侧转换处理。

1. dict.conf : file_key 是实际路径吗？mcf stringkv 分别是什么意思，如何使用？

规范上讲 file_key 就应该是实际路径。（由于历史遗留配置文件中存在不一致的情况，所以平台没有绑定死，而是由策略同学遵循规范配置 dict.conf）
conf_dict 表的自定义 file_type，有 stringkv (字符串 kv 词表)、gray 灰名单 (灰名单 kv)、mcf(set 名单类，黑白、行业名单)、ipmap（有序 set）等等，而在 dic_meta 词表元信息表，该 file_type 变为 subtype，并归类到 3 个 type 下：kv、set、orderset。所有子类别及其父类别在 DictMetaConstant 常量类中配置了。
页面新建词表的时候，就要选择 file_type。

1. project 指什么，如何创建一个新的 project

这里的 project 在代码里实际写作 second_project，业务上代表一条过滤流，每条流下有一套 conf_file，最终部署时部署到 AFS 的一个文件夹。如 "click-policy"。
代码里的 project 则是对应一个 icode 代码库，通过 id 对应到下面的多个 second_project。除此之外，其余数据表的 project_id 均对应 second_project_id。
如何创建一个新的 project：[产品线接入文档](https://ku.baidu-int.com/knowledge/HFVrC7hq1Q/pKzJfZczuc/04j2Ioutfp/Id_RDyde5sbp7o)

1. casespace 里怎么避免上线冲突？

目前的 casespace 为了简单避免冲突，一旦一个同学发起构建（点构建按钮），就给当前 project 加个锁标志位 lock=true，直到构建上线过程全部完毕 (finish_deploy)，才把锁置为 false，以允许另一个同学进行构建。

1. 构建生成的文件怎么部署到线上？

部署上线过程有两个：一个是用空间修改数据构建好的文件部署推送到线上 AFS；一个是全部上线成功后，数据库里面 个人空间修改的数据 cover 线上空间。
其中，过程一：

- 主代码都在 deploymanager.py。
  - 先 save 部署记录
  - 然后调用 \_deploy(self, deploy_record, action, env, src_dir) ,实际就是拿到 project、record、build_path、deploy_path，系统异步执行一个 bash 命令。
  - bash 命令调用执行 script/deploy.py，实际就是在 AFS 把构建文件从 build_path 复制到 deploy_path。成功后调用 request_django 回调平台接口，将 record 置为 " 完成 " 状态

1. 怎么 cover_data (空间代码合入)

也就是问题 8 的过程二：

- finish_deploy 后，调用 deploy_manager.cover_data()
  - 跟 build 的 generate 前面过程差不多，先 diff 拿到修改的空间配置，拿出增删改的 casespace 数据
  - 拿到增、改的 casespace 数据锁对应的 online 数据（id 相同但 scope=1）
  - 备份 online 数据
  - 个人空间覆盖 online 空间，
    - add 的，新增一条，id 自增 1，version=0，scope=1
    - update 的，各字段覆盖线上那条数据，其中 id 不动，version+1
    - delete 的，status 置为 delete
- 释放上线锁
- 删除当前 project 下的 mysql 缓存

1. Process 类里面的 sections 有什么用

Process 类会导入 定义的所有 section 到 process.sections 数组中，只起到定义当前 process 有哪些 section 的作用，至于流程执行的先后与 sections 数组无关。
