【项目】特征中心

【目标】通过特征中心平台，实现特征统一管理、低成本特征复用

【工作】

1. 服务接入

- 完成全部AS、Flink流的服务托管

2. 特征复用

复用表达升级：

- 支持和迁移动态词表、三方、二阶等特征，完成了动态词表的表达重构
- 动态词表特征复用时支持维度映射，适配维度不一致和多维度使用场景

复用通路更多：

- 打通 TM 引用 AS 自累积特征，满足转化方向 anti2 特征读取需求
- 打通 Flink 引用 AS 特征，满足渠道方向使用 tradeService 黑词表的需求
- 支持 AS block 级别复用、同服务/同场景复用

复用性能提升：保障AntiService可用性

- 支持 redis 读缓存，提高读取性能
- 支持 care 重写，用于圈定读取流量和排除异常值，减少读取量

3. 特征可视化

- 动态词表特征关联静态词表，满足动态词表的自动添加、删除的审批需求，覆盖100%活动、电商的动态词表

4. 全局黑库

- 设计和支持全局动态词表，满足活动方向黑库建设需求，同时适配特征可视化追溯

【成果】

- 完成了全部服务的配置迁移和上线托管；
- 实现了特征统一管理、低成本复用的目标；
- 升级特征表达，支持更多复用场景，满足业务需求。

【我的职责】

方案设计、功能开发、日常运维

【自评】
特征中心是22年底刚做完初版，今年的主要工作是服务接入和细节完善。在服务迁移过程中，对每条流的迁移都做到了充分策略分析，也发现了一些初期方案不能覆盖的问题，及时完善了特征表达并推进AS、Flink升级。最终依据策略无损的上线方案，实现了稳定迁移。此外也积极响应业务需求，持续完善了特征复用的通路和功能。特征中心项目算是已经基本完成。

【项目】神盾策略管理平台

【目标】完善神盾平台基础建设，跟进重点需求，提高策略调研和上线效率

【工作】

1. 模拟过滤和测试验证

- TM：支持多天级别任务，适配多天窗口特征累积，优化过滤效果；支持小时级别任务，避免检索方向数据量过大导致任务失败
- AntiService：支持上线前的测试验证功能，满足策略配置的提前测试验证需求
- Flink：支持全场景的平台化操作，包括模拟过滤、策略回溯、工程测试

2. AS 策略上线提速

- 解决tradeService多人同时上线阻塞问题，平均阻塞时长从5h缩短到0.5h
- 策略的 Judge 从 product 拆分到 policy，简化策略操作

3. 策略和上线稳定性

- AS 策略隔离：支持 AntiService 策略分场景隔离的平台功能
- Flink工程上线：提高 Flink 工程上线的稳定性
- 预览构建提速：解决TM policy 预览构建过慢的问题, 提速65%
- 策略精准Diff：策略上线的 diff 修改为与线上的精准 diff, 规避策略最终上线的潜在风险
- 策略预警：支持 cpc 和 dformat 准实时产出开 judge 策略词表, 用于策略报警监控

4. 合规改造需求

- 权限：服务管理等重要模块、词表信息的权限收敛
- 词表合规：支持神盾词表元信息合规改造, 增加审批功能
- 技术栈合规：nodejs 版本升级到 20.x

【成果】

对上线合规性、稳定性、效率都有较大提升。

- 合规性：审批、上线 全流程记录
- 稳定性：提供了 AS、FLink 测试验证环境，规避上线风险
- 效率：解决AS同时上线阻塞问题，阻塞时长从5h缩短到0.5h

【我的职责】

方案设计、功能开发、日常运维

【自评】
今年神盾的主要工作在策略稳定性方面，做的还不错。支持了 AntiService测试验证、Flink模拟过滤功能的平台化集成支持，提供策略的提前验证。针对性解决了策略上线阻塞等问题，保障了神盾策略上线的稳定性。此外对一些使用体验问题做了优化，比如 Flink策略依赖查找、词表查找、策略开 Judge等。明年希望可以更针对性地提升下用户体验，比如策略快速查询、预览代码快速查找。
