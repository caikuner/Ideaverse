## 1、最大的难点，是细节 UI 设计

作为个人开发者，在没有设计师和团队其他成员的帮助之下，要把一个网站的 UI 细节做到很精美的程度，是一件非常非常困难的事情。最大的时间消耗，就是在思考应该怎么设计自己网站的样式。

为了这个事情，我还专门整了几本 UI 设计方面的书来看、在抖音关注了很多设计博主、在 figma 上面参考了许多设计稿、也会每天都会看看 dribbble，收藏了一大堆设计方案

但毕竟不是专业的，我可能可以把某一个小的模块做得很精美，但是要在整站坚持统一的设计元素，就基本上做不到了。因为每个模块的内容都不一样，稍作变动出来的效果就很差。

所以这也是我为什么在网站立项之初，没有任何想法要支持暗黑模式的原因。一方面是一种风格都设计不好，再来一种肯定也不行。另外一方面，是工作量确实有点大。

但是...

想要暗黑模式的用户实在有点多，隔三差五的就有人问我啥时候支持暗黑模式。我都不知道怎么应对了..

没打算支持啊 ～

但是后面还是没顶住。我知道难度很大，结果投入进去，没想到难度这么大。这简直比我当年手撕大型复杂 K 线图系统损耗的精力还要多。

我们以这张图举例。

![图片](https://mmbiz.qpic.cn/sz_mmbiz_png/Kn1wMOibzLcGb76EagNQefJP3YGbC3aYpVfJsGnXDpmwLLQwiargjl7PK4ptnJIRCylicIGrTAllYZwd0YIJGRfMw/640?wx_fmt=png&from=appmsg&tp=webp&wxfrom=5&wx_lazy=1)

晃眼一看，大家第一反应是不是感觉很简单。

第一眼的感觉，和真实的实践是完全不一样的，就这么个小玩意儿，我搞了一下午才真正复刻出来。在暗黑模式下，这里面临了两个难点

**第一、背景色的层次感很难调** 。因为网页的背景色已经是暗色了，还要在暗色下的前提之下，调出来三个比较柔和的层次色，作为一个外行。是真的有点难。出现的色差很容易就过大或者过白。最后发现，这种层次感，是通过在黑底色的情况下，然后混合了一层透明度为 `5%` 的白色实现的。

真是太妙了。 `tailwindcss` 的实现如下所示

```
<div className='bg-gray-950'>
  <div className='bg-white/5'></div>
</div>
```
![图片](https://mmbiz.qpic.cn/sz_mmbiz_png/Kn1wMOibzLcGb76EagNQefJP3YGbC3aYp8VMsgFNfocXYufGFmtdIInVgqldqv4wwlg0UtXyOHX71D8Mu6wdLzQ/640?wx_fmt=png&from=appmsg&tp=webp&wxfrom=5&wx_lazy=1)

看截图中所示，这里使用了 `color-mix()` 的 css 函数，它标记接收两个 `<color>` 值，并返回在指定颜色空间、指定数量混合后的颜色。基础使用如下所示

```
color-mix(in lch, plum, pink);
color-mix(in lch, plum 40%, pink);
color-mix(in srgb, #34c9eb 20%, white);
color-mix(in hsl longer hue, hsl(120 100% 50%) 20%, white);
```

**第二、边框很难弄** 。在暗黑模式下，如果我们直接使用 1px 的边框，会感觉非常明显，直接就破坏了设计感。做不到仅仅只是浅浅的一点光泽的这种感觉。如下图所示，大家可以仔细感受一下

直接用 `border` 的样式会更加的明确和显眼，不柔和。

![图片](https://mmbiz.qpic.cn/sz_mmbiz_png/Kn1wMOibzLcGb76EagNQefJP3YGbC3aYphfG8dDhv9aMWp53bXKRhuq2289lHfX5IlWeic6PbGXu1AIYYyvJQKKw/640?wx_fmt=png&from=appmsg&tp=webp&wxfrom=5&wx_lazy=1)

因此，这个边框，不能使用 `border` 来实现，这里只能选择 `box-shadow` 。 `box-shadow` 语法虽然简单，但是，要调出一个好的效果，就不是那么容易了，这里我使用了如下代码来实现

```
<div className='bg-white/5 dark:inset-ring dark:inset-ring-white/10 ...'>
</div>
```

## 2、暗黑模式的基础方案

站在 CSS 的角度来说，支持 `dark mode` 需要有两种基础方案。

一种是 CSS 变量。我们可以通过如下的方式定义自己的属性

```
div {
  ---border-color: brown;
}
```

自定义属性必须以 `--` 开头。

规则集所指定的选择器定义了自定义属性的可见作用域。在使用过程中，我们通常会将其定义在根节点的伪类下，这样就可以在 HTML 文档的任何地方访问该变量

```
:root {
  ---border-color: brown;
}
```

在具体的元素属性中使用时，我们会使用 var () 函数来访问 css 变量对应的值

```
div {
  border-color: var(---border-color);
}
```

我们可以在 CSS 中定义不同的自定义属性可见作用域

```
:root {
  /* 浅色模式变量 */
  --color-background: #ffffff;
  --color-text: #333333;
  --color-primary: #2563eb;
  --color-secondary: #e2e8f0;

/* 其他设计系统变量... */
}

[data-theme="dark"] {
/* 深色模式变量 */
  --color-background: #1a1a1a;
  --color-text: #f5f5f5;
  --color-primary: #3b82f6;
  --color-secondary: #4b5563;
}
```

然后在 CSS 中使用他们

```
body {
background-color: var(--color-background);
color: var(--color-text);
transition: background-color 0.3s ease, color 0.3s ease;
}

button {
background-color: var(--color-primary);
color: white;
}

.card {
background-color: var(--color-secondary);
}
```

然后通过改变父级元素的 `data-theme` 为 `dark` 即可以生效。

这是主题切换的思路，但是通常情况下，暗黑模式还要求支持跟随系统自动切换，因此，这种方案的支持程度就还不够。

因此，另外一种方案，就是通过媒体查询监听系统主题的变化来改变颜色，具体的语法如下所示，这里展示了 `tailwindcss` 在实现暗黑模式，所用到的底层语法

```
.dark\:text-red-400 {
  @media (prefers-color-scheme: dark) {
    color: var(--color-red-400) /* oklch(0.704 0.191 22.216) */;
  }
}
```

必要时刻，我们也可以在 JS 中，监听到系统主题的变化

```
const prefersDarkScheme = window.matchMedia('(prefers-color-scheme: dark)');

// 监听系统主题变化
prefersDarkScheme.addEventListener('change', e => {
  const newTheme = e.matches ? 'dark' : 'light';
  document.documentElement.setAttribute('data-theme', newTheme);
  localStorage.setItem('theme', newTheme);
});
```

## 3、tailwindcss dark: 变体

好消息就是，由于我的整个网站，从一开始就使用了 `tailwindcss` ，并且大部分基础组件，从一开始就是自己基于 `tw` **手撸** 的，在适配时，几乎没有遇到什么外接三方依赖带来的烦恼

所以，在大部分时候，我可以直接利用 `tw` 的方案来做深色模式的适配。

代码大概如下所示

```
<div className='text-red-500 dark:text-red-400'>
  ...
</div>
```

并且，由于借助了 `cursor` ，所以他可以自动在任何使用了颜色的地方，加上暗黑模式的代码，极大的提高了我的适配效率。

但可惜的是， `cursor` 仅仅只是按照色值取反的思路给我推荐了主题。例如，我原本的颜色是 `text-gray-600` ，cursor 就会自动给我推荐一个 `text-gray-300` ，如果只是简单应付一下群友的需求，这肯定是足够了。

但是如果想要做好，在深色模式下有自己的设计在里面，随着需求的不断增加， `cursor` 提供的方案就越来越不行了，因此，第一个版本出来的挺快，但是后续又调了很久。

除此之外， `tailwindcss` 还是无法覆盖项目中的所有场景。最显著的问题，就是代码块和图片的处理比较麻烦

## 5、图片主题切换

为了能够更清晰的讲解一些复杂的知识点，我的网站内容里面，还包含了大量的图片演示。特别是在《爆锤面试官之 React 原理面试》和《图解算法》中，图片特别多

本来刚开始是不准备做图片的适配的，但是，大家看如下所示，亮色的图片在暗黑模式下实在是太亮了。这有点接受不了啊。

![图片](https://mmbiz.qpic.cn/sz_mmbiz_png/Kn1wMOibzLcGb76EagNQefJP3YGbC3aYpKicKp5jvlSNMykucQmoc3mEqwaDHTIibuAiaM6DFCuOpMEnernNZLTreg/640?wx_fmt=png&from=appmsg&tp=webp&wxfrom=5&wx_lazy=1)

所以，我又开始思考怎么让图片也支持深色模式。

之前学习 `next.js` 的时候，被 `next.js` 的官网深深震撼到了，因为他们家官网居然支持图片的主题切换，这也太帅了 ～

研究了一下发现他们是使用了两张图片来根据图片切换。确实做的很好，佩服！可是等到我自己要来支持图片主题切换的时候，要准备两张图真的好麻烦，所以我就在想，有没有其他的思路

例如把我们的这些图片，处理成一个数据格式，然后内置一个解析器来渲染出来。当然，并不是一开始就有这个思路，这个太新奇了，以前没这样想过。我是在某一次跟学生上课的聊天过程中，灵光一闪觉得这样做在理论上行得通。

于是调研了一下发现，好巧不巧，我使用的绘图工具： `excalidraw` 刚好就支持我的这种想法，并且他们已经有非常成熟的开源工具，还支持了 React 组件。 **不得不说，React 的生态真的太给人惊喜了**

我们可以把直接在 ` excalidraw.com` 上绘制好的图片，保存成为一个如下的 JSON 格式数据

```
{
  "type": "excalidraw",
  "version": 2,
  "source": "https://excalidraw.com",
  "elements": [
    ...
  ]
  ...
}
```

然后，我们需要在项目中引入这个渲染工具

```
yarn add @excalidraw/excalidraw
```

然后在如下的组件中渲染出来就可以了。

```
<Excalidraw
  initialData={{
    ...initialData,
    appState: {
      ...
    },
    theme={theme}
  }}
/>
```

大家可以通过 `excalidraw` 的开发文档，了解更多详细的信息

https://docs.excalidraw.com/

看一下我最终实现的效果，美滋滋

![图片](https://mmbiz.qpic.cn/sz_mmbiz_gif/Kn1wMOibzLcGb76EagNQefJP3YGbC3aYpBTNyPI6y6hLibiaE1y3rh0Jk8PL43tBicjhlFd8Z3GjZAqBu2ibB6o4YCA/640?wx_fmt=gif&from=appmsg&tp=webp&wxfrom=5&wx_lazy=1)

除此之外，还会有更多的开发难度，因为这种渲染方式，是不支持页面宽度响应的，因此，在后续的开发中，我又折腾了很久，把这些图片本身就具备的响应式能力给支持上。

虽然不能完全还原图片的丝滑，但是从结果上来看，勉强可以接受。

## 6、总结

由于站内元素非常多，所以要做到整站支持暗黑模式，是一件工程量非常大的事情。国内大多数网站都会在这一个需求上面选择放弃。

不过好在，经过我一个月左右的折腾，我的网站已经迈出了坚实的一步，在 `tailwindcss` 的加持之下， `usehook.cn` 的暗色模式已经初步成熟，欢迎大家访问体验。

还有许多不完美的地方，也会陆续更新完善。 `usehook.cn` 必将成为国内最好的 `React` 学习网站之一 (ง・\_・)ง
